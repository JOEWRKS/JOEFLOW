## 1. 근거

### 1.1 요청 (원문)

> "지금 오목 게임을 AI 보조 도우미가 실제로 작동하는 AI 대국 오목 게임으로 만들어봐. 서로 대화를 주고받는게 아니라 추천 수와 경우의 수, 상대의 예상 수와 각 위치 별 승률을 가시적으로 알려주는 제한적 알고리즘을 쓰는 거임. 상호작용하는 LLM이 아니라."

요청에서 읽어낸 요구 후보 (`INFERRED_INTENT`이므로 후보로만 취급한다):

| ID 후보 | 내용 | 근거 강도 |
| --- | --- | --- |
| R-a | AI와 실제로 대국한다 (AI가 상대로서 둔다) | 원문에 명시 |
| R-b | 추천 수를 보여준다 | 원문에 명시 |

| R-f | "가시적으로": 글보다 판 위의 시각 표시를 중심으로 한다 | 원문에 명시 |
| R-g | 결정적이고 제한된 알고리즘을 쓴다. LLM이나 대화형 상호작용은 쓰지 않는다 | 원문에 명시 |

### 1.2 기존 프로젝트에서 확인한 사실 (관찰된 구현이며 의도의 증거는 아님)

- **제품:** "함께 배우는 AI 오목". 15×15 자유 오목이고 금수가 없다. 6목 이상도 승리다. 사람은 흑으로 선공하고 AI는 백이다. 브라우저 로컬 시제품이며 TypeScript + Vite, 순수 DOM, Web Worker 1개로 동작한다. 서버, 로그인, 외부 AI API는 없다. (`README.md`, `BRIEF.md`, `ROADMAP.md`)
- **AI는 이미 존재한다.** `src/engine.ts`가 전술 검사(즉시 승리, 유일 방어)와 **후보를 최대 12개로 제한한 2 ply minimax**를 한다. 평가는 572개의 길이 5 창에 가중치(1/8/64/512)를 준 휴리스틱 H이고 ±100,000으로 제한된다. Worker 응답이 2초를 넘으면 1 ply "간이 분석"으로 내려간다. (`src/engine.ts`, `src/analysis-client.ts`, `Library/engine-notes.md`)
- **현재 보조 표시는 모두 단일 값이고 문장 중심이다.**
  - 추천은 1곳뿐이다. 고리 하나와 1–2문장의 이유를 보여준다.
  - 상대 예상 수도 1곳뿐이다(점선 고리). 실제 AI 응수에 그대로 재사용한다.
  - 내 수 평가는 미리 정해 둔 문장 표(승리, 방어, 놓친 위협, 연결 등)로 한다.
  - 판 요약은 3단계 문구다(흑 유리 / 백 유리 / 차이 없음, 임계값 H=±64).
  - 문구는 "혼자 고민하지 않아도 괜찮아요", "어디에 두고 싶으세요?"처럼 대화체다. 요청의 "대화를 주고받는 게 아니라"와 관련 있을 수 있다.
- **"경우의 수"를 보여주는 기능이 없다.** 후보 수, 후보별 점수, 탐색 노드 수, 수순(PV)을 화면에 내보내지 않는다. 내부 점수는 선택에만 쓰고 표시하지 않기로 의도적으로 정했다. (`engine-notes.md`의 "2 ply 점수는 내부에서만 사용")
- **승률 표시는 명시적으로 금지돼 있다.** `BRIEF.md`는 "실제 승률을 산출·검증할 근거가 없다면 임의의 퍼센트를 승률처럼 내놓지 마세요"라고 한다. ROADMAP A2/U1, README, DESIGN도 "승률 게이지 없음", "숫자 승률 표시하지 않음"이라고 적는다. → **이번 요청 R-e와 직접 충돌한다(CONTRADICTION).** 다만 BRIEF의 금지는 조건부("근거가 없다면")다. 실제로 계산하고 그 의미를 밝히는 승률이면 BRIEF의 문언과 양립할 수 있다.
- **AI 대국은 수동 단계로 진행된다.** 흑을 확정하면 "내 수 검토" 화면이 나오고, 사용자가 `AI 응수 보기`를 눌러야 백이 둔다. 요청의 "실제로 작동하는 AI 대국"이 자동 응수를 뜻할 수 있다(추론).
- **기존 부가 기능:** 착수는 선택 후 확정하는 2단계다. 되돌리기(P4)는 흑+백을 함께 취소하고 redo는 없다. 종료 후 복기(P5)는 이전/다음 수를 보며 당시 해설을 표시한다. 새 게임, 키보드 조작, live 알림, 1440×900·390×844 두 화면 크기를 검증했다. 단위 62개·E2E 18개가 통과한 과거 근거가 있다.
- **비동기 계약:** `gameId`, `revision`, `requestId`, `key`, `engineVersion`(`local-2ply-v1`)가 모두 맞을 때만 결과를 적용한다. 새 분석 데이터를 추가하면 이 프로토콜과 `validResult`를 확장해야 한다.
- **범위 밖이었던 것:** 렌주 금수, 온라인 대전, 프로 수준 엔진, 학습 DB. 나중 아이디어로 "난이도 선택, 기보 저장, 심화 분석"이 적혀 있다(`ROADMAP.md` 25행). TASK의 최신 기록은 "다음 작업은 사용자 피드백 후 설명/위협 표시·기보·난이도/수읽기 중 선택"이라고 한다. 이번 요청이 그 선택에 해당한다.
- **검증되지 않은 것:** AI 강도, 교육 효과, 실물 기기 성능, 사용자 시각 승인. (`ISSUES.md`, `ROADMAP.md` 124행)

### 1.4 활성화되는 Grill 관점 (판단)

- Core는 항상 활성이다.
- `async`가 활성이다. Worker 분석, 진행형 계산, 시간 제한, 늦은 결과 폐기가 있기 때문이다.
- `auth`, `money`, `permission`, `file-upload`, `destructive-action`은 해당 없음이다. 새 게임 확인 같은 기존 파괴 동작은 바뀌지 않는다.

## 2. 사용자에게 물을 미결 결정 (우선순위순)

순위는 interrogation-engine의 기준을 따랐다. 파급 범위, 핵심 흐름, 비즈니스 규칙 순으로 높다. 실제로는 한 번에 한 질문만 하고, 답을 받을 때마다 의존 항목을 다시 평가한다.

### Q1. "위치별 승률"을 무엇으로, 어떻게 산출할 것인가 — 최우선

- **왜 중요한가:**
  - 기존 BRIEF 제약(임의 승률 금지)과 정면으로 충돌한다.
  - 엔진 설계, 성능 예산, 화면 표기, 검증 기준 전부가 이 답에 달려 있다.
  - 정의가 잘못되면 사용자를 오도하는 숫자가 된다.
- **영향:** R-e, R-b, 엔진/Worker 프로토콜, 판 오버레이, 범례·도움말 문구, 수용 기준, BRIEF/ROADMAP의 승률 금지 조항.
- **선택지:**
  - **A. 모의 대국(몬테카를로 playout) 비율.** 각 후보 칸에 두었다고 가정하고, 제한된 정책(전술 우선 + 무작위성)으로 끝까지 N회 모의 대국을 둔다. 흑이 이긴 비율을 "%"로 표시하고 "모의 대국 N회 기준 추정"이라고 명시한다.
    - 장점: 실제로 계산한 빈도라 BRIEF의 "근거 없는 임의 숫자"에 해당하지 않는다. 숫자의 뜻을 정확히 말할 수 있다.
    - 단점: 계산량이 크다. 표본이 작으면 값이 흔들린다. 실제 사람과 둔 승률로 보정되지 않았다.
  - **B. 휴리스틱 평가를 0–100 지수로 변환.** 기존 H 점수를 곡선(예: 로지스틱)으로 "% 같은 지수"로 바꾼다.
    - 장점: 빠르고 결정적이다.
    - 단점: 확률이 아니므로 "승률"이라고 부르면 BRIEF 위반이다. "유리도 지수" 같은 다른 이름이 필요하다.
  - **C. 범주형 유불리 맵.** 탐색 결과로 칸마다 "필승 / 유리 / 비슷 / 불리 / 필패(즉시 위협 방치)" 등급을 색으로 표시한다. 숫자 %는 없다.
    - 장점: 정직하고 가볍다.
    - 단점: 사용자가 원한 "승률" 숫자가 아니다.
  - **D. A와 C 결합.** 확정 사실(즉시 승리, 즉시 패배 방치)은 범주 표식으로 덮어 쓰고, 나머지 후보 칸은 모의 대국 %를 표시한다.
- **권고: D.**
  - 사용자가 명시한 "승률"을 실제 계산 근거가 있는 숫자로 제공한다.
  - "모의 대국 N회 기준, 보정되지 않은 추정"이라는 뜻을 화면에 상시 표기한다. 그러면 BRIEF의 조건부 금지 취지(근거 없는 숫자 금지)를 지킬 수 있다.
  - 즉시 승리나 패배처럼 확실한 칸에는 "100% / 0%"라는 확률 오해를 주지 않는다.
  - 이 선택을 하면 **BRIEF와 ROADMAP의 "승률 표시 안 함" 서술을 이번 결정으로 대체한다는 점도 함께 확인**받는다.
- **결과:** A나 D를 고르면 미결 결정 2(표시 범위)와 9(계산 시간)가 중요해진다. B나 C를 고르면 9의 중요도가 낮아진다.

### Q2. 승률(또는 유불리)을 판의 어느 칸까지 표시할 것인가

- **왜 중요한가:** 225칸 전부를 계산하면 시간이 많이 들고 화면이 숫자로 뒤덮인다. "각 위치별"의 범위가 화면 밀도와 성능을 정한다.
- **선택지:**
  - **A. 모든 빈칸.** 먼 칸은 회색 "계산 안 함"이 아니라 실제 값을 표시한다.
  - **B. 탐색 후보 칸만(약 10–20칸).** 기존 돌에서 거리 2 이내이고 평가 상위인 칸이다. 나머지 칸은 표시하지 않고 "후보 밖"이라고 범례에 적는다.
  - **C. 상위 N칸(예: 5칸)만 숫자를 붙이고, 나머지 후보 칸은 색 농도로만 표시한다.**
- **권고: B, 숫자는 상위 5칸에만 표기하고 나머지 후보 칸은 색 농도와 접근성용 이름으로 표시한다(B+C 절충).**
  - 계산 가능한 범위이고, 모바일 358px 판에서도 읽을 수 있다.
  - 사용자가 후보 밖의 칸을 선택하면 그 칸만 따로 계산해 보여주는 동작을 함께 제안한다.

### Q3. "경우의 수"는 무엇을 뜻하는가

- **왜 중요한가:** 정의가 셋 이상으로 갈리고, 각각 화면 구성 요소가 다르다.
- **선택지:**
  - **A. 탐색 규모 수치.** "후보 14곳 × 상대 응수 12곳 = 168가지를 비교함", 모의 대국 횟수 등을 보여준다.
  - **B. 후보 수 목록.** 상위 3–5개 후보를 좌표, 승률, 짧은 근거 태그(공격/방어/연결)와 함께 순위표로 보여준다.
  - **C. 예상 수순(분기 미리보기).** 후보 하나를 고르면 "내 수 → 상대 응수 → 내 다음 수"를 번호 붙은 반투명 돌로 판 위에 보여준다.
  - **D. A + B + C 모두.**
- **권고: B + C를 기본으로 하고, A는 패널 하단의 한 줄 요약으로 둔다(사실상 D이지만 A는 보조).** "경우의 수"를 가장 시각적으로 보여주는 것은 후보 순위와 분기 수순이고, 탐색 규모 숫자는 "실제로 계산하고 있다"는 신뢰를 주는 보조 정보다.
- **결과:** C를 고르면 수순 깊이(현재 2 ply → 3수 이상 표시)가 미결 결정 8과 연동된다.

### Q4. 상대 예상 수를 몇 개, 어떤 형태로 보여줄 것인가

- **선택지:**
  - **A. 기존처럼 1곳만.**
  - **B. 상위 3곳을 순위 번호(①②③)가 붙은 점선 고리로 표시하고, 각각 "이 응수 후 흑 승률"을 함께 보여준다.**
  - **C. 상위 3곳을 고리로 표시하되 승률 없이 순위만 보여준다.**
- **권고: B.** 요청이 "상대의 예상 수"를 별도 항목으로 강조했다. 응수가 여러 개일 수 있다는 사실이 "확정된 미래가 아니다"라는 BRIEF 원칙을 시각적으로 지켜 준다.
- **추가 확인:** 예상 수를 **착수 전에도**(선택한 후보 칸에 대해) 보여줄지, 기존처럼 **착수 후에만** 보여줄지도 함께 묻는다. 권고는 "선택한 칸 기준으로 착수 전에도 표시"다. 그래야 추천과 경우의 수가 한 화면에 모인다.

### Q5. AI 대국 진행 방식: 자동 응수인가, 수동 단계 유지인가

- **현재:** 흑을 확정하면 검토 화면이 나오고, 사용자가 `AI 응수 보기`를 눌러야 백이 둔다.
- **선택지:**
  - **A. 자동 응수.** 흑을 확정하면 짧은 지연(예: 0.6초) 뒤 백이 자동으로 둔다. 직전 수 분석은 패널에 남는다.
  - **B. 기존 수동 단계 유지.**
  - **C. 설정으로 전환(기본값은 자동).**
- **권고: A.** "실제로 작동하는 AI 대국"이라는 표현은 끊김 없는 대국에 가깝다. 직전 수 분석은 기록 영역에 남으므로 학습 정보는 잃지 않는다. 설정 토글(C)은 범위를 늘리므로 필요할 때 추가한다.

### Q6. 기존 문장형 해설과 대화체 문구를 어떻게 할 것인가

- **왜 중요한가:** 요청은 "서로 대화를 주고받는 게 아니라"라고 했다. 하지만 현재 제품 정체성("함께 배우는", 초보자용 이유 설명)과 BRIEF의 "추천 이유 제공"은 문장 해설에 기대고 있다.
- **선택지:**
  - **A. 데이터 중심 패널로 바꾼다.** 수치, 순위, 태그, 판 표시로 대체한다. 문장은 칸마다 한 줄 근거 태그(예: "즉시 승리", "4목 방어", "열린 3 형성")로 축소하고, 대화체 인사·격려 문구는 없앤다.
  - **B. 기존 해설을 그대로 두고 수치 패널을 추가한다.**
  - **C. 수치 패널을 기본으로 하고, 해설은 "자세히" 접힘 영역에 둔다.**
- **권고: C.** 요청의 "대화형이 아님"을 충족하고 시각 중심으로 만들면서, 이미 검증된 사실 기반 해설 자산과 BRIEF의 "이유 제공"을 잃지 않는다. 대화체 안내 문구는 중립적 레이블로 바꾼다. 제품명("함께 배우는 AI 오목")을 바꿀지는 별도로 확인한다(아래 Q11).

### Q7. 보조 표시를 언제 켜고, 누구 차례에 보여줄 것인가

- **선택지:**
  - **A. 항상 켬. 흑(내) 차례에만 계산한다.**
  - **B. 기본으로 켬. 레이어별 토글을 둔다(승률 맵 / 후보·수순 / 상대 예상). 흑 차례에만 계산한다.**
  - **C. B에 더해, AI(백) 차례에도 "AI가 고려한 후보와 승률"을 보여주는 투명성 표시를 한다.**
- **권고: B.** 스스로 생각해 보고 싶을 때 끌 수 있어야 대국 게임으로서도 성립한다. AI 차례의 투명성 표시(C)는 자동 응수(Q5-A)와 함께 쓰면 화면이 빠르게 바뀌어 혼란스럽다. 대신 "직전 AI 수의 당시 후보"를 기록 영역에서 보는 방식으로 대체를 제안한다.

### Q8. AI 강도와 탐색 깊이를 바꿀 것인가, 난이도 선택을 둘 것인가

- **현재:** 후보 12개, 2 ply, 강도 미검증.
- **선택지:**
  - **A. 현 엔진의 강도를 유지하고 시각화만 추가한다.**
  - **B. 시간 예산 안에서 깊이를 늘린다.** 알파베타와 반복 심화로 4 ply 내외, 위협 수(연속 4/열린 3) 우선 탐색을 쓴다. 단일 난이도다.
  - **C. B에 더해 난이도 2–3단계를 선택하게 한다.** 쉬움은 낮은 깊이나 무작위성으로 구현한다.
- **권고: B.** "실제로 작동하는 AI 대국"과 경우의 수 수순 표시(Q3-C)를 위해서는 3수 이상의 수순이 필요하다. 난이도 선택은 ROADMAP의 나중 아이디어이고 범위를 키우므로 이번에는 제외하고, 원하면 후속으로 진행한다. **강도를 수치로 주장하지 않는다는 기존 원칙은 유지한다.**

### Q9. 분석 대기 시간 예산과 정확도의 교환

- **왜 중요한가:** 모의 대국 승률(Q1-A/D)은 시간을 더 쓸수록 정확해진다. 현재는 2초 제한 후 간이 분석으로 내려간다.
- **선택지:**
  - **A. 고정 예산(예: 데스크톱 1.5초).** 완료 후 한 번에 표시한다.
  - **B. 진행형 표시.** 결과가 계산되는 대로 갱신하고, 상한(예: 3초) 또는 "충분 표본" 도달 시 멈춘다. 모의 대국 수(N)를 표시한다.
  - **C. 사용자가 "더 분석" 버튼으로 연장한다.**
- **권고: B.** 기다리는 동안에도 화면이 "실제로 계산 중"임을 보여 준다. 표본 수가 함께 보여서 숫자의 신뢰도를 정직하게 전달한다. 상한 도달 전에도 착수할 수 있다. C는 필요하면 후속으로 진행한다.

### Q10. 되돌리기와 복기에서 분석 기록을 어떻게 다룰 것인가

- **선택지:**
  - **A. 복기 화면에서 각 수 당시의 승률 맵, 후보, 예상 수를 그대로 다시 보여준다(저장된 스냅샷).**
  - **B. 복기에서는 기존처럼 해설만 보여준다.**
  - **C. 복기할 때 해당 국면을 다시 분석한다.**
- **권고: A.** "내가 둔 수가 당시 몇 순위였고 승률이 얼마였나"를 보는 것이 이 기능의 가장 큰 학습 가치다. 저장된 스냅샷을 쓰면 다시 계산하는 비용과 무작위성으로 인한 불일치가 없다. 되돌리기는 기존 계약대로 취소한 분기의 기록을 지운다.

### Q11. 제품 정체성: 학습 도우미인가, 대국 게임인가 (이름과 첫 화면 문구)

- **선택지:**

- **권고: B 쪽으로 기울지만, 사용자 표현만으로는 단정할 수 없어 확인이 필요하다.** 우선순위가 낮다(문구와 첫 화면에만 영향).

## 3. 담당자가 정할 비중요 결정 (agent-autonomous 후보)

모두 국소적이고 되돌리기 쉬운 세부 사항이다. 2절의 답이 바뀌면 다시 검토한다.

- **승률 숫자 형식:**
  - 정수 %로 쓰고 소수점은 없다.
  - 승률은 흑(사용자) 관점으로 통일한다. 범례에 "흑 기준"을 표기한다.
  - 표본이 작으면(예: N<50) 숫자 옆에 "≈"를 붙이고 흐리게 표시한다.
- **히트맵 색:**
  - 기존 팔레트를 쓰는 단일 계열 순차 색이다. 유리는 녹색 계열 `#1F5D49`, 불리는 주의색 `#8B3F20`이다.
  - 색만으로 구분하지 않도록 숫자, 순위 번호, 모양(추천은 원형 고리, 예상은 점선 고리)을 함께 쓴다.
- **오버레이 겹침 우선순위:** 실제 돌 > 선택 테두리 > 추천 1위 고리 > 상대 예상 고리 > 수순 미리보기 돌 > 히트맵 배경.
- **수순 미리보기 표기:** 반투명 돌에 1, 2, 3 번호를 붙인다. 실제 돌과 혼동되지 않도록 불투명도는 50% 이하로 하고 외곽선을 점선으로 한다.
- **후보 순위표:** 상위 5개 기본, 행 높이 44px 이상이다. 행을 클릭하면 해당 칸이 선택되고 수순 미리보기가 나온다(착수하지는 않는다).
- **근거 태그 어휘:** 즉시 승리 / 즉시 방어 / 열린 4 / 4 방어 / 열린 3 / 연결 / 일반. 이미 있는 `Explanation.kind`에 대응시킨다.
- **모의 대국 정책 세부:**
  - 전술 우선(즉시 승리·방어) 후 근접 후보 중 가중 무작위로 고른다.
  - 같은 판에서 재현할 수 있도록 판 key 기반 시드를 쓴다.
  - 무승부는 0.5승으로 셈한다.
  - 수치는 엔진 참고 문서에 기록한다.
- **엔진과 프로토콜:**
  - `ENGINE_VERSION`을 올린다(예: `local-search-v2`).
  - `Analysis`에 `candidates[]`, `opponentReplies[]`, `principalVariation[]`, `stats{nodes, playouts, elapsedMs}`를 추가하고 `validResult` 검증을 확장한다.
  - 진행형 결과는 같은 requestId의 partial 메시지로 보낸다.
- **진행형 갱신 주기:** 약 250ms마다 갱신한다. 동작 감소 설정에서는 전환 애니메이션 없이 값만 바꾼다.
- **자동 응수 지연:** 0.6초 내외다. 분석 중 상태 표시는 기존 "생각하는 중…" 위치를 재사용한다.
- **레이어 토글 상태:** 메모리에만 보관하고, 새로고침하면 기본값(켬)으로 돌아간다. 기존 정책상 저장하지 않는다.
- **간이 분석(시간 초과) 때의 표시:** 승률 맵을 숨기고 "간이 분석: 한 수 위협만 확인" 배지를 단다. 후보는 전술 후보만 보여준다.
- **접근성:**
  - 각 칸의 이름에 "H8, 빈칸, 추천 1위, 흑 승률 약 62%"처럼 분석값을 덧붙인다.
  - live 알림은 "분석 완료, 추천 H8"까지만 하고 225칸을 읽지 않는다.
- **모바일 배치:** 판 → 후보 순위표 → 상대 예상 → 탐색 요약 순으로 세로 배치한다. 토글은 판 바로 위에 칩 형태로 둔다.
- **기존 2단계 착수(선택 → 확정)와 키보드 조작:** 유지한다.
- **검사:**
  - 단위 검사: 후보·승률 범위 0–100, 즉시 승리/패배 칸의 범주 표식, 시드 결정성, 프로토콜 검증.
  - E2E 검사: 두 화면 크기, 토글, 자동 응수 중복 착수 방지, 늦은 partial 결과 폐기.
- **문서:** ROADMAP·README·engine-notes의 "승률 없음" 서술은 Q1의 결정에 맞춰 정정한다. BRIEF는 보존 대상이므로 수정하지 않고, 결정 기록으로 대체 관계만 남긴다.

### 4.1 화면 구성 (단일 화면, SCR 후보)

**SCR-A 대국 화면**

- **상단 바:**
  - 제품명
  - 차례 / 수 번호
  - `새 게임`
  - `규칙·도움말`
  - 레이어 토글 칩 3개: `승률 맵` `후보·수순` `상대 예상`
- **판 영역(데스크톱 왼쪽 약 520px, 모바일 최대 358px):**
  - 실제 돌, 마지막 수 표식, 승리선.
  - **승률 히트맵:** 후보 칸의 배경 색 농도. 상위 5칸에는 정수 % 숫자를 표시한다.
  - **확정 칸 표식:** 즉시 승리는 "승", 즉시 패배 방치는 "!" 아이콘과 주의색이다.
  - **추천 1위:** 녹색 원형 고리 + "추천".
  - **선택한 칸:** 사각 테두리.
  - **상대 예상 수:** 선택한 칸(없으면 추천 1위) 기준 상위 3곳을 ①②③ 점선 고리로 표시한다.
  - **수순 미리보기:** 후보 순위표에서 행을 고르거나 칸을 선택하면 번호 붙은 반투명 돌로 3수 내외를 보여준다.
- **분석 패널(데스크톱 오른쪽 약 350px, 모바일은 판 아래):**
  1. **형세 막대:** 현재 국면의 흑 추정 승률(가로 막대 + %). 아래에 "모의 대국 N회 기준 · 보정되지 않은 추정"을 상시 표기한다.
  2. **추천 수 순위표 (경우의 수):** 순위, 좌표, 흑 승률 %, 근거 태그. 상위 5행이며 행을 고르면 판에서 선택하고 미리보기를 보여준다.
  3. **상대 예상 수:** 선택한 수 기준으로 ①②③ 좌표, "이 응수 후 흑 승률", 근거 태그를 보여준다.
  4. **탐색 요약 한 줄:** "후보 14곳 · 응수 비교 168가지 · 모의 대국 1,400회 · 1.2초".
  5. **행동 영역:**
     - `H8에 두기` (확정)
     - `추천 위치 선택`
     - `↶ 되돌리기`
     - 분석 중에는 진행 표시가 나오고 착수도 할 수 있다.
  6. **직전 수 기록:**
     - 내가 둔 수가 당시 몇 순위였고 승률이 얼마였는지(예: "H9 · 당시 3순위 · 54%")를 보여준다.
     - 직전 AI 수와 그때의 후보도 보여준다.
     - `자세히`를 펼치면 기존 사실 기반 해설 문장이 나온다.
- **종료 오버레이(판 위 카드):** 승자 또는 무승부, 승리선, `대국 복기`, `새 게임`.
- **복기 모드:**
  - `이전 수 / 다음 수 / 종료 판으로`.
  - 각 수 당시의 승률 맵, 후보, 예상 수 스냅샷을 판과 패널에 그대로 다시 보여준다.
  - "복기 중 · n수 · 당시 분석" 배지를 단다.
  - 착수와 토글 외의 조작은 비활성이다.

### 4.2 상태 (UX state 초안)

| 상태 | 표시 |
| --- | --- |
| Default(첫 화면) | 규칙 3줄과 `첫 게임 시작`. 대화체 문구는 쓰지 않는다 |
| Loading/Partial(분석 중) | 히트맵과 순위표가 진행형으로 갱신된다. N이 증가하고, 표본이 적은 값은 흐리게 "≈"로 표시한다. 착수할 수 있다 |
| Success(분석 완료) | 값을 고정하고 live 알림 "분석 완료, 추천 H8"을 낸다 |
| Timeout/Error(간이 분석) | 승률 맵을 숨기고 "간이 분석" 배지와 `다시 분석`을 보여준다. 판은 보존한다 |
| AI 차례 | "백이 두는 중…". 판 입력을 막고, 새 게임·되돌리기는 기존 규칙대로 허용한다 |
| Completed(종료) | 결과 카드를 보여준다. 분석 표시는 지운다 |
| Replay | 당시 스냅샷을 보여주고 착수를 비활성화한다 |
| Disabled | 선택이 없으면 확정 버튼 비활성과 그 이유를 보여준다. 되돌릴 수 없으면 되돌리기를 비활성화한다 |
| Empty(빈 판) | 추천 H8. 승률 맵은 H8 주변 후보만 표시한다 |
| Unauthenticated / Permission / Offline | 해당 없음(로컬 전용, 계정 없음) |

### 4.3 사용자 흐름 (FLOW 후보)

**FLOW-1 기본 대국 루프**

1. `첫 게임 시작` → 빈 판, 흑 차례, 분석을 시작한다(진행형).
2. 사용자가 히트맵, 추천 순위표, 탐색 요약을 본다.
3. 사용자가 칸이나 순위표 행을 고른다(선택만 하고 판은 바뀌지 않는다). 판에 선택 칸 기준 상대 예상 ①②③과 수순 미리보기가 나오고, 패널에 해당 칸 승률이 나온다.
   - 대안: 후보 밖 칸을 선택하면 그 칸만 즉석 분석하고 "후보 밖 · 계산 중"을 보여준다.
4. `H8에 두기`로 흑 1개를 확정한다. 직전 수 기록에 "당시 n순위 · %"를 저장한다.
5. 승리나 만판이면 FLOW-3으로 간다.
6. 아니면 "백이 두는 중…"을 보여주고 짧은 지연 뒤 백이 자동으로 착수한다. 직전 AI 수 기록을 저장한다.
7. 백 승리나 만판이면 FLOW-3으로 간다. 아니면 1단계의 분석부터 반복한다.

**FLOW-2 분석 실패 / 시간 초과**

- 분석 상한을 넘거나 오류가 나면 간이 분석으로 전환한다. 승률 맵을 숨기고 배지와 `다시 분석`을 보여준다.
- 사용자는 그대로 착수하거나 재분석할 수 있다.
- AI 응수 분석이 실패해도 판은 보존하고 간이 응수로 진행한다. 이 경우 AI 돌이 중복으로 놓이지 않는다.

**FLOW-3 종료와 복기**

- 결과 카드에서 `대국 복기`를 누르면 0수부터 이전/다음으로 이동하며 당시 분석 스냅샷을 본다. `종료 판으로`를 누르면 결과 카드로 돌아간다.
- `새 게임`을 누르면 기록을 모두 초기화한다.

**FLOW-4 되돌리기**

- 직전 흑 수와 그 뒤 AI 수를 취소한다. 기존 계약을 따른다.
- 복원한 판에서 다시 분석한다. 취소한 분기의 분석 스냅샷은 삭제하고, 늦게 도착한 분석 결과는 폐기한다.

**FLOW-5 레이어 토글**

- 칩을 끄면 해당 오버레이와 패널 섹션이 접힌다. 계산은 계속하므로 다시 켜면 즉시 보인다.
- 모든 레이어를 끄면 순수 대국 모드가 된다.

### 4.4 수용 기준 초안 (AC 후보, 관찰 가능 형태)

- AC-a: 흑 차례마다 추천 순위표 상위 행(최대 5개)에 좌표, 0–100 정수 승률, 근거 태그가 표시된다. 표시 값은 현재 판 key와 일치하는 분석에서만 나온다.
- AC-b: 즉시 승리 칸은 "승" 표식, 즉시 패배를 방치하는 칸은 "!" 표식으로 표시되고 확률 숫자로 표시되지 않는다.
- AC-c: 모든 승률 표시 근처에 "모의 대국 N회 기준 추정" 표기가 있다. N은 실제로 수행한 횟수와 같다.
- AC-d: 칸을 선택하면 그 칸 기준 상대 예상 수 최대 3곳이 순위 번호와 함께 표시된다.
- AC-e: 흑을 확정한 뒤 사용자 조작 없이 백이 정확히 1개 착수한다. 연타, 되돌리기, 새 게임이 겹쳐도 백 돌이 중복되지 않는다.
- AC-f: 시간 초과나 오류 시 간이 분석 배지가 보이고, 승률 숫자가 표시되지 않으며, 판은 보존된다.
- AC-g: 복기의 각 수에서 당시 저장한 분석 스냅샷이 표시된다. 재계산하지 않는다.
- AC-h: 1440×900과 390×844에서 판, 패널, 확정 버튼을 조작할 수 있다. 오버레이가 겹쳐도 각 표식의 라벨을 읽을 수 있다.
- AC-i: LLM, 외부 API, 네트워크 호출 없이 동작한다.
