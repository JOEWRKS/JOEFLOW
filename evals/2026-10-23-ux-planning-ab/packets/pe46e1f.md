# 기능 기획 초안 — AI 대국 + 가시적 분석 도우미

- 대상: `project/` (함께 배우는 AI 오목, 로컬 TypeScript + Vite 시제품)
- 기준일: 2026-10-23
- 단계: JOEFLOW V2의 **DISCOVER 완료 + CLOSE 준비**. 사용자 질문 직전에서 멈춤. `state.json` 생성, 스크립트 실행, 구현은 하지 않음.
- 이 문서는 권위 원본이 아니다. 결정이 내려지면 `state.json`에 기록하고 이 문서는 그 투영이 된다.

## 1. 근거

### 1.1 요청 원문에서 읽은 것

> "지금 오목 게임을 AI 보조 도우미가 실제로 작동하는 AI 대국 오목 게임으로 만들어봐. 서로 대화를 주고받는게 아니라 추천 수와 경우의 수, 상대의 예상 수와 각 위치 별 승률을 가시적으로 알려주는 제한적 알고리즘을 쓰는 거임. 상호작용하는 LLM이 아니라."

| 요청 요소 | 해석 | 확실도 |
| --- | --- | --- |
| AI 대국 오목 게임 | 사람이 AI와 실제로 한 판을 두는 게임 | 높음 (이미 존재: 사람 흑, AI 백) |
| AI 보조 도우미가 실제로 작동 | 판 위·옆에 분석 정보가 실시간으로 보이는 도우미 | 중간. 현재 도우미가 "작동하지 않는다"고 느낀 이유는 모름 |
| 추천 수 | 현재 판에서 둘 만한 위치 | 높음 (이미 1곳 표시) |
| 경우의 수 | **불명확.** 후보 여러 개 목록 / 수순 가지(변화도) / 탐색한 국면 수 등 여러 뜻 가능 | 낮음 |
| 상대의 예상 수 | 내가 둔 뒤(또는 둘 경우) 상대가 둘 만한 위치 | 중간 (현재는 착수 후 1곳만) |
| 각 위치 별 승률 | 빈 교차점별 승리 가능성 숫자 | 뜻은 분명하지만 **기존 BRIEF와 충돌** (1.3) |
| 가시적으로 | 판 위 표시(색·숫자·고리)와 패널 | 높음 |
| 제한적 알고리즘, LLM 아님 | 규칙/탐색 기반 로컬 엔진. 대화형 생성 모델·외부 API 없음 | 높음. 기존 L1 제약과 일치 |

### 1.2 프로젝트에서 확인한 사실 (관찰, 의도 아님)

- **이미 로컬 AI가 실제로 작동한다.** `src/engine.ts`의 즉시 승리/방어 우선 + 후보 12개 제한 2 ply minimax, `src/worker.ts`의 Web Worker, 2초 watchdog 후 간이(1 ply) 분석(`analysis-client.ts`). 외부 API·LLM 없음. 문장은 고정 템플릿(`explainMove`, `reviewMove`).
- 현재 화면(`src/main.ts`)이 보여주는 것:
  - 사람 차례: **추천 1곳**(원형 고리) + 이유 1문장 + `추천 위치 선택`.
  - 착수 후: 내 수 해설 + **가능한 백의 대응 1곳**(점선 고리) + "상대가 언제나 이렇게 둔다는 뜻은 아니에요".
  - 판 요약 3단계 문구(`positionSummary`: 흑 우세 / 백 우세 / 차이 없음). 숫자 없음.
- 대국 흐름(`src/controller.ts`): `intro → thinking(흑) → human → [확정] → thinking(백) → review → [AI 응수 보기 클릭] → thinking(흑) …`. **AI 응수는 사용자가 버튼을 눌러야 놓인다** (학습용 단계 진행).
- 엔진 내부에 이미 있는 값: 후보 목록(최대 12 + 전술 후보), 각 후보의 2 ply minimax 점수, 정적 평가 H(572개 5칸 창 가중치 합). 현재는 **후보별 점수·순위를 외부로 내보내지 않음** (`Analysis`에 `move` 하나만).
- 함께 존재하는 기능: 되돌리기(P4), 종료 후 복기(P5), 새 게임 확인, 키보드 조작, 1440×900·390×844 확인, 프로덕션 외부 통신 0.
- 모바일(390×844) 실제 캡처 `work/evidence/mobile-review.png`: 판 폭 약 358px → 교차점 간격 약 22px. 판 아래에 행동 영역, 그 아래 설명 카드가 세로로 이어짐.
- 성능 근거: 2 ply는 2초 watchdog 안에서 동작. 중반 정식 성능 측정과 저사양 기기 측정은 **미실시**(ROADMAP P3, TASK).
- 문서 권한: BRIEF = 보존할 사용자 제품 목표. ROADMAP·DESIGN·engine-notes = 담당자 선택안(사용자 시각 승인 없음).

### 1.3 충돌 (사용자 결정 없이는 해소 불가)

| ID | 충돌 | 근거 |
| --- | --- | --- |
| CON-1 | 요청 "각 위치 별 승률" ↔ BRIEF "실제 승률을 산출·검증할 근거가 없다면 임의의 퍼센트를 승률처럼 내놓지 마세요" | BRIEF.md, README "숫자 승률… 표시하지 않습니다", 화면 문구 "승률이나 최종 결과의 예측이 아닙니다", DESIGN "승률 게이지는 두지 않는다" |
| CON-2 | 요청 "AI 대국 게임" ↔ 현재 학습용 단계 흐름(AI 응수를 버튼으로 진행) | controller `review` 단계, ROADMAP "선택한 학습 흐름" (담당자 선택안이므로 바꿀 수 있음) |
| CON-3 | 요청 "제한적 알고리즘" + 많은 가시 정보 ↔ 2초 watchdog과 모바일 22px 교차점 | analysis-client 2000ms, 모바일 캡처 |

## 2. 사용자에게 물을 미결 결정 (우선순위 순)

질문은 한 번에 하나씩, Q1부터 묻는다. 앞 질문의 답에 따라 뒤 질문이 사라지거나 바뀔 수 있다.

### Q1. "승률" 숫자를 무엇으로 계산하고 어떻게 부를까? (최우선)

- 왜 중요한가: 요청의 핵심 표시이자 BRIEF 금지 조항과 정면 충돌. 엔진 구조, 계산 시간, 모든 화면 문구, 도움말이 이 답에 달림.
- 근거: CON-1. 현재 엔진에는 확률을 내는 부분이 없다. 내부 점수 H는 연결 모양 가중치 합이라 그대로 %로 바꾸면 BRIEF가 금지한 "임의의 퍼센트"가 된다.
- 선택지:
  - **A. 시뮬레이션 승률 (추천).** 각 후보 위치에 둔 뒤 이 AI 두 개가 끝까지(또는 정해진 수까지) 빠르게 두어 보는 대국을 N판 돌리고, 흑이 이긴 비율을 표시. 화면 이름은 "시뮬레이션 승률" 또는 "이 AI끼리 N판 중 승리 비율"처럼 계산 방식을 함께 표기. 무엇을 세었는지가 분명해 BRIEF의 "산출 근거" 조건을 만족시킬 수 있음. 대가: 계산 시간이 크게 늘고(Q7과 연결), 실제 사람 상대 승률은 아님을 계속 밝혀야 함. 같은 판이라도 판 수가 적으면 값이 흔들림(고정 시드로 재현성 확보 가능).
  - B. 평가 점수를 0–100 지표로 변환. 계산은 빠르지만 "승률"이라고 부르면 BRIEF 위반. "유리도 지수"처럼 다른 이름이 필요하고 요청의 "승률"과 어긋남.
  - C. 숫자 없이 색 단계(유리 / 비슷 / 불리)만. BRIEF는 그대로 지키지만 요청의 "승률"은 충족하지 못함.
  - D. 평가 점수를 그대로 %로 표시하고 "승률"이라 부름. BRIEF 금지 조항을 사용자가 명시적으로 철회해야만 가능. 추천하지 않음.
- 추천: **A**. 이름과 단서 문구를 함께 고정하고, 즉시 승리/즉시 패배처럼 확정된 칸은 %가 아니라 "바로 승리", "막지 않으면 패배"로 표시.
- 결과 영향: 엔진(롤아웃 정책·난수 시드), Worker 시간 예산, 표시 문구, 도움말, BRIEF 대응표, DESIGN "승률 게이지 없음" 문구.

### Q2. 승률(또는 평가)을 판의 어느 위치까지 보여줄까?

- 왜 중요한가: "각 위치 별"을 글자 그대로 하면 빈칸 최대 225곳. 계산량과 모바일 가독성이 이 답으로 결정됨.
- 근거: 모바일 교차점 간격 약 22px(캡처). 숫자 2–3자리를 225곳에 쓰면 판이 읽히지 않음. A안 기준 225곳 × N판은 2초 안에 어려움.
- 선택지:
  - **A. 후보 위치만 (추천).** 엔진이 고른 후보(기본 상위 5곳, 최대 12곳)에 숫자. 나머지 빈칸은 표시 없음. 판 위에는 상위 3–5곳만 숫자, 나머지 후보는 패널 목록에.
  - B. 모든 빈칸에 색 히트맵, 숫자는 상위 몇 곳만. 전체 분포가 보이지만 Q1-A와 결합하면 계산이 매우 무거움(색은 정적 평가로, 숫자는 시뮬레이션으로 따로 계산하면 두 지표가 섞이는 문제).
  - C. 사용자가 누른 칸만 즉석 계산. 가볍지만 "가시적으로 한눈에"가 약해짐.
- 추천: **A**, 단 사용자가 후보 밖 빈칸을 선택하면 그 칸도 계산해 보여주는 C를 보조로 결합(선택 후 확정 전 "이 자리의 승률"이 보임).

### Q3. "경우의 수"는 무엇을 보여주는 것인가?

- 왜 중요한가: 요청 단어 중 가장 뜻이 넓다. 패널 구조가 완전히 달라짐.
- 선택지:
  - **A. 후보 수 목록 + 각 후보의 이어지는 수순 (추천).** 상위 N개 후보마다 "내가 여기 → 상대 예상 → (승률)"을 한 줄로. 2 ply 탐색 결과를 그대로 보여주므로 추가 계산이 적음.
  - B. 수순 나무(트리) 펼치기. 후보 → 상대 응수 여러 개 → 다시 내 수. 깊이 볼 수 있지만 모바일에서 복잡하고 제한적 탐색 깊이(2 ply)를 넘는 정보는 없음.
  - C. 숫자 요약만: "둘 수 있는 빈칸 N곳, 살펴본 후보 M곳, 계산한 국면 K개".
- 추천: **A**, 패널 머리에 C의 한 줄 요약을 곁들임.
- 추가 확인(답이 A일 때): 목록 기본 개수 3 / 5 중 무엇. 담당자 기본값은 5(모바일은 3 펼침 + 더보기).

### Q4. "상대의 예상 수"를 언제, 몇 개 보여줄까?

- 근거: 현재는 내가 둔 **뒤**에만 1곳.
- 선택지:
  - **A. 착수 전 후보마다 1개 + 착수 후 상위 3개 (추천).** 착수 전에는 Q3-A 목록 안에 각 후보의 상대 최선 응수, 착수 후에는 상대 응수 상위 3곳을 판에 점선 고리+순위 번호로.
  - B. 착수 후에만, 상위 3개.
  - C. 지금처럼 착수 후 1개.
- 추천: **A**. "예상"은 확정된 미래가 아니라는 기존 단서 문구 유지.

### Q5. AI는 내 착수 후 자동으로 둘까, 지금처럼 버튼으로 진행할까?

- 왜 중요한가: "AI 대국 게임"이라는 표현은 끊김 없는 대국을 떠올리게 하지만, 현재는 매 수마다 `AI 응수 보기`를 눌러야 함(CON-2). 대국 템포와 "예상 수를 읽을 시간" 사이의 선택.
- 선택지:
  - **A. 자동 응수 + 직전 상대 예상과 실제 수 비교 표시 (추천).** 확정하면 AI가 짧은 지연 후 바로 둠. 상대 예상 고리는 AI가 두기 전 잠깐, 그리고 둔 뒤 "예상 1순위와 같음/다름"으로 남김.
  - B. 지금처럼 수동 진행 유지.
  - C. 설정으로 선택(기본 자동).
- 추천: **A**. 단, Q6에서 도우미를 켠 상태라면 C로 바꾸는 것도 합리적이라 함께 확인.

### Q6. 도우미 표시를 끌 수 있어야 하나?

- 근거: 추천·승률이 항상 보이면 "대국"이라기보다 정답 보기에 가까워질 수 있음. 현재는 끄는 기능 없음.
- 선택지:
  - **A. 도우미 켜기/끄기 토글, 기본 켜짐 (추천).** 끄면 판 위 표시와 패널이 숨고 AI 대국만 진행. 계산은 꺼진 동안 하지 않음.
  - B. 항상 켜짐.
  - C. 항목별 토글(추천/승률/상대 예상 각각).
- 추천: **A**. C는 나중 확장으로.

### Q7. 분석 결과를 얼마나 기다릴 수 있나? (정확도와 대기 시간의 교환)

- 왜 중요한가: Q1-A를 택하면 시뮬레이션 판 수가 정확도와 대기 시간을 동시에 결정. 사용자가 체감하는 품질.
- 근거: 현재 2초 watchdog, 저사양 측정 없음.
- 선택지:
  - **A. 점진 표시 (추천).** 먼저 추천·순위를 즉시(현 2 ply 수준) 보여주고, 승률 숫자는 계산되는 대로 채움. 최대 약 3초에서 멈추고 표본 수를 함께 표시("120판 기준"). 기다리지 않고 바로 둘 수 있음.
  - B. 모든 숫자가 준비될 때까지 기다림(약 1–3초, 착수 막힘).
  - C. 빠른 근사만(약 0.5초, 표본 적음).
- 추천: **A**.

### Q8. 되돌리기·복기에서 분석 표시를 어떻게 다룰까?

- 근거: 되돌리기는 복원한 판에서 추천을 다시 계산함. 복기는 당시 해설을 저장해 보여주며 재계산하지 않음.

  - C. 복기에서 선택한 국면을 새로 계산.

## 3. 담당자가 정할 비중요 결정

아래는 되돌리기 쉽고 제품 의미를 바꾸지 않는 세부 사항이다. 사용자 질문 없이 담당자가 정하고 기록한다. 사용자가 원하면 언제든 바꿀 수 있다.

| 항목 | 담당자 결정 |
| --- | --- |
| 승률 관점 | 항상 **사람(흑) 기준**으로 표시. 상대 예상 수의 숫자도 "그 수가 놓였을 때 나의 승률"로 통일 |
| 숫자 형식 | 정수 %, 소수점 없음. 표본 수 함께 표시. 표본 30판 미만이면 숫자 대신 "계산 중" |
| 확정 칸 표기 | 즉시 승리 = "바로 승리", 단일 방어 칸 = "막아야 함", 막기 불가 = "위험" 문구. 100%/0% 숫자 쓰지 않음 |
| 시뮬레이션 정책(Q1-A일 때) | 즉시 승리 → 즉시 방어 → 근처 후보 중 정적 평가 상위에서 가중 무작위. 최대 수 제한 도달 시 무승부로 셈. 판+차례 키 기반 고정 시드로 같은 판은 같은 결과 |
| 후보 개수 | 판 위 숫자 상위 5곳(모바일 3곳), 패널 목록 기본 5곳 |
| 판 위 표현 | 후보: 연한 색 원 + 순위 번호, 승률은 색 농도로도 이중 표현(색만으로 구별하지 않음). 상대 예상: 기존 점선 고리 + 순위 번호. 현재 범례에 항목 추가 |
| 터치·키보드 | 기존 "누르면 선택, 확정 버튼으로 착수" 유지. 패널 목록 행을 누르면 그 칸이 선택됨. 각 칸의 aria-label에 순위·승률 추가 |
| Worker 프로토콜 | `Analysis`에 `candidates[]`(좌표, 순위, 2 ply 점수 순서, 상대 최선 응수, 승률, 표본 수) 추가. `ENGINE_VERSION` 올림. 점진 결과는 같은 requestId의 부분 메시지로 보내고 기존 일치 검사(gameId/revision/requestId/key) 그대로 적용 |
| 시간 제한 | 기본 분석(추천·순위)은 기존 2초 watchdog 유지. 시뮬레이션은 별도 예산(약 3초)으로 끊고, 초과 시 그때까지의 표본으로 확정 표시 |
| 간이 분석 시 | 간이(1 ply) 상태에서는 승률 숫자를 숨기고 기존 "간이 분석" 안내 유지 |
| 자동 응수 지연(Q5-A일 때) | 약 0.6초. 동작 감소 설정에서는 지연 없이 표시 |
| 기존 문구 정리 | "승률이 아닙니다" 류 문구는 Q1 결정에 맞춰 수정. BRIEF 원문은 보존하고 ROADMAP에 결정 근거 연결 |
| 검사 | 엔진 단위검사(후보 목록·시드 재현성·확정 칸 표기), 상태 검사(점진 결과의 늦은 도착 무시), E2E(두 화면에서 패널·판 표시·토글·자동 응수) |

### 4.2 사용자 흐름

**FLOW-1 첫 대국**
1. 사용자가 앱을 연다 → 안내(흑 선공, 다섯 잇기, 도우미 설명 한 줄)를 본다.
2. `첫 게임 시작` → 빈 판에 추천 H8과 "바로 둘 수 있어요" 표시. 승률은 빈 판이라 "비슷함"으로 표기.
3. 판의 칸 또는 목록 행을 눌러 선택 → `H8에 두기`로 확정.
4. AI가 짧은 지연 후 백을 둔다. 두기 직전 상대 예상 3곳이 점선으로 보였다가 실제 돌로 바뀌고, "예상 1순위와 같음"이 표시된다.
5. 새 판에 대한 후보·승률이 먼저 순위, 이어서 숫자 순으로 채워진다. 반복.

**FLOW-2 후보 밖에 두기**
- 사용자가 후보가 아닌 칸을 선택 → 그 칸의 승률을 추가 계산해 "이 자리 41% (추천 H9 62%)"로 비교 → 그래도 확정 가능. "추천과 다르다 = 실수"로 표현하지 않음.

**FLOW-3 위급 상황**
- 상대 즉시 승리 칸이 있으면 목록 최상단에 "막아야 함", 판에 경고 표시. 두 곳 이상이면 "한 번에 막기 어려움". 내 즉시 승리 칸이 있으면 "바로 승리".

**FLOW-4 기다리지 않고 두기**
- 승률이 채워지는 중에도 선택·확정 가능. 확정하면 진행 중 계산은 취소되고 늦은 결과는 버린다.

**FLOW-5 실수 복구**
- `↶ 되돌리기` → 내 직전 수와 AI 응수 취소 → 복원한 판에서 후보·승률 다시 계산.

**FLOW-6 도우미 끄기**
- 토글 끔 → 판 표시·패널 숨김, 계산 중지 → 다시 켜면 현재 판을 계산.

**FLOW-7 종료와 복기**
- 승리/무승부 → `대국 복기` → 이전/다음 수마다 당시 후보·승률·상대 예상과 실제 둔 수를 함께 확인. 새 게임으로 초기화.

**실패·예외**
- Worker 오류·시간 초과 → 간이 분석으로 진행, 승률 숨김, 재분석 버튼.
- 새 게임·되돌리기 중 도착한 이전 결과 → 무시(기존 일치 검사).
- 새로고침 → 판과 기록 초기화(기존과 동일).
