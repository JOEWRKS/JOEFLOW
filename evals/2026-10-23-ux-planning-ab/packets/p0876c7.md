# AI 대국 오목 + 가시적 분석 보조 — 기획 준비안 (DISCOVER·CLOSE 준비 단계)

- 작성일: 2026-10-23
- 대상: `project/` (함께 배우는 AI 오목, 로컬 TypeScript + Vite 시제품). 읽기 전용으로 조사했고 아무것도 수정하지 않았다.
- 적용 절차: planning-skill(JOEFLOW) V2의 DISCOVER → CLOSE 중 **첫 사용자 질문 직전까지**. `state.json`은 만들지 않았고 스크립트도 실행하지 않았다. 따라서 이 문서는 정식 권위가 아닌 준비 메모이며, 아래 ID(EV/SF/CT/UNK/AD)는 이후 state에 옮길 때 쓸 임시 ID다.

## 2. 사용자에게 물을 미결 결정 (우선순위 순)

질문은 실제로는 **한 번에 하나씩**, 위에서부터 묻는다. 앞 답에 따라 뒤 질문의 선택지가 바뀔 수 있다.

### UNK-01 — "각 위치별 승률"을 무엇으로 보여줄 것인가 (최우선)

- 왜 중요한가: BRIEF의 명시 금지(CT-1)를 바꾸는 결정이고, 엔진 설계(자체 대국 시뮬레이션 필요 여부), 계산 시간, 화면 표현, 문구의 정직성 모두를 결정한다. 가장 파급이 크다.
- 근거: EV-P2, EV-P3, EV-P4. 현재 평가값 H는 연결 모양의 경험적 가중치이며 확률이 아님.

| 선택지 | 내용 | 장점 | 단점/결과 |
| --- | --- | --- | --- |
| A. **시뮬레이션 승률** (권장) | 후보 칸마다 이 앱의 AI끼리 그 자리에서 끝까지(또는 정해진 수까지) N판을 빠르게 두어 본 결과 비율을 "%"로 표시. "이 AI끼리 N판 두어 본 결과, 실제 승률 아님"과 표본 수를 함께 표기. | 요청한 "승률 %"를 그대로 주면서 **산출 근거가 실제로 존재**해 BRIEF의 조건(근거가 있으면 허용)을 충족. 검증 가능(같은 시드→같은 값). | 계산이 무거워 **상위 후보 칸에만** 숫자 가능. 값은 이 AI 수준에 종속되며 실제 사람 상대 승률이 아님. 대기 시간 증가. |
| B. 유불리 등급 히트맵 | 모든 빈칸(또는 주변 칸)을 탐색 점수로 3~5단계 색+기호 등급(매우 좋음~나쁨)으로 표시. 퍼센트 없음. | 빠르고 모든 칸 표시 가능. BRIEF 그대로 유지. | 사용자가 요청한 "승률"이라는 형식과 다름. |
| C. 평가 점수를 퍼센트로 환산 | H값을 곡선으로 0~100%로 바꿔 "승률"로 표시. | 구현 쉬움, 보기에 직관적. | **근거 없는 퍼센트** → BRIEF 위반. 권장하지 않음. |
| D. A+B 혼합 | 판 전체는 B의 등급, 상위 후보 몇 곳만 A의 시뮬레이션 %. | 넓은 시야+요청한 숫자 둘 다. | 표현 두 종류를 사용자에게 구별시켜야 함. |

- **권장: D (판 전체 등급 + 상위 후보에만 시뮬레이션 %)**. 단일안으로 고르면 A. C는 BRIEF를 정면으로 어기므로 사용자가 명시적으로 원해도 "승률" 대신 "점수"로 부르는 조건을 붙여 다시 확인한다.
- 사용자가 A/D를 고르면 BRIEF의 해당 문장에 대한 **사용자 명시 변경 승인**으로 기록해야 한다(원본 파일은 보존, 변경 결정은 별도 기록).

### UNK-02 — 이 기능을 기존 앱에 어떻게 들일 것인가 (제품 형태)

- 왜 중요한가: 화면 구조·흐름·기존 검사 회귀 범위를 결정. "AI 대국 게임으로 만들어봐"(CT-2)와 "실제로 작동하는"(CT-3)의 뜻을 함께 확인한다.
- 함께 확인할 사실 질문: "지금 앱의 추천 고리·해설·`AI 응수 보기`를 써 보셨나요? 써 봤다면 무엇이 '작동하지 않는다'고 느껴졌나요?" (예: 버튼을 눌러야 AI가 둬서 대국 느낌이 없음 / 추천이 1곳뿐 / 숫자가 없음)

| 선택지 | 내용 | 장점 | 단점 |
| --- | --- | --- | --- |
| A. **기존 화면 확장** (권장) | 지금 대국 화면에 분석 패널·판 위 오버레이를 추가. 기존 해설 카드는 유지하되 축소. | 되돌리기·복기·키보드 등 검증된 기능 재사용, 회귀 위험 최소. | 화면 정보가 많아짐(특히 휴대폰). |
| B. 학습 모드와 대국 모드 분리 | 시작 화면에서 "배우며 두기(현행)"와 "AI 대국(분석 보조)"을 고름. | 두 경험이 섞이지 않음. | 화면·상태·검사 2배. 첫 범위로 큼. |
| C. 기존 학습 흐름을 대국 중심으로 교체 | 문장 해설 단계를 없애고 분석 시각화 중심의 대국 화면으로 바꿈. | 요청에 가장 직접적. | 기존 "함께 배우는" 정체성·검사 다수 폐기. |

- **권장: A**. 단, UNK-06에서 AI 응수를 자동으로 바꾸면 대국 느낌은 A에서도 확보된다.

### UNK-03 — "경우의 수"는 무엇을 보여주는가

- 왜 중요한가: 엔진 출력 형식(EV-P5에는 후보 목록·수순이 없음)과 패널 구성을 결정.

| 선택지 | 내용 | 비용/한계 |
| --- | --- | --- |
| A. **상위 후보 목록 + 각 후보의 이어지는 수순 한 줄** (권장) | 예: "1위 H8 → 백 H7 → 흑 G7" 처럼 후보 3~5개와 각각 짧은 예상 수순(탐색 깊이만큼). 판에서 후보를 고르면 그 수순을 번호 돌로 미리보기. | 탐색 깊이만큼만 보여 줌(깊이 표기 필수). |
| B. 후보 목록만 | 순위·등급(또는 %)만, 이어지는 수 없음. | 단순하지만 "경우의 수" 느낌 약함. |
| C. 펼칠 수 있는 수순 트리 | 내 수 → 상대 응수 여러 갈래 → 내 재응수… 를 트리로 탐색. | 정보량·구현량 큼, 휴대폰에서 어려움. |

```text
            -> 백 승리/만판? -> [S3 종료]
            -> 아니면 [S2 흑 차례: 분석 중]으로 반복
[어느 때나] 되돌리기 -> 직전 흑 수(+이후 백 수) 취소, 그 판 재분석/캐시 사용
[어느 때나] 보조 끄기 -> 오버레이·패널 숨김, 대국 계속 (추천 계산 생략 여부는 담당자 결정)
[어느 때나] 새 게임 -> 진행 중이면 확인 -> 분석 취소, 새 판
[S3] 대국 복기 -> [S4] 이전/다음 수, 당시 분석 표시 -> 종료 판으로 / 새 게임
```

**분기와 예외 (조건부로 유지)**
- 분석이 시간 초과·실패: 그 수에 한해 "간이 분석" 표시, 히트맵·%는 "계산하지 못함", 재분석 버튼. 대국과 자동 응수는 간이 결과로 계속. (다른 정상 수에는 적용되지 않음)
- 시뮬레이션 %만 늦음: 등급·후보는 먼저 보이고 %는 채워질 때까지 "계산 중". 그 사이 사용자가 착수하면 늦은 %는 버림.
- 자동 응수 대기 중 되돌리기/새 게임: 대기 중인 백 착수 취소, 늦은 결과 적용 안 함.
- 즉시 승리 수가 있을 때: 1위 후보로 "바로 이김" 사실 표시(% 대신 확정 사실).
- 상대 즉시 승리 위협이 둘 이상: "한 번에 막기 어려움" 기존 사실 표시 유지.
- 사용자가 추천 밖 칸을 둠: 그 칸 기준 등급·예상 수 그대로 표시, "실수"로 단정하지 않음.
