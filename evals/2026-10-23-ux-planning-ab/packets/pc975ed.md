## 1. 근거

### 1.1 사용자 요청 해석 (원문 기준)

> "지금 오목 게임을 AI 보조 도우미가 실제로 작동하는 AI 대국 오목 게임으로 만들어봐. 서로 대화를 주고받는게 아니라 추천 수와 경우의 수, 상대의 예상 수와 각 위치 별 승률을 가시적으로 알려주는 제한적 알고리즘을 쓰는 거임. 상호작용하는 LLM이 아니라."

| 요청 요소 | 명확한 정도 | 메모 |
| --- | --- | --- |
| AI와 대국한다 | 명확 | 현재 앱도 사람(흑) 대 로컬 AI(백) 구조다. |
| "AI 보조 도우미가 **실제로 작동하는**" | **애매** | 지금의 도우미가 "작동하지 않는다"고 느끼는 이유가 불분명하다. 후보: (a) 추천이 한 곳뿐이고 근거가 문장뿐이다. (b) AI가 `AI 응수 보기`를 눌러야 두기 때문에 실제 대국처럼 느껴지지 않는다. (c) AI가 약하다. |
| 추천 수 | 부분 명확 | 지금은 한 곳만 보여준다. 몇 곳을 보여줄지는 미정이다. |
| 경우의 수 | **애매** | 후보 수 여러 개, 수순(이어지는 몇 수), 남은 빈칸 수 가운데 무엇을 뜻하는지 정해야 한다. |
| 상대의 예상 수 | 부분 명확 | 지금은 내가 둔 뒤 백의 대응 한 곳만 보여준다. 여러 곳을 가능성과 함께 보여줄지는 미정이다. |
| 각 위치별 승률 | **기존 제약과 충돌** | 아래 1.3의 C1을 본다. |
| 가시적으로 알려준다 | 명확 | 판 위의 시각 표시가 필요하다. 문장 카드만으로는 부족하다. |
| 제한적 알고리즘, LLM 아님, 대화형 아님 | 명확 (근거로 해결) | BRIEF의 "외부 AI API 불필요, 로컬 AI"와 같다. 생성형 모델이나 채팅 UI는 범위 밖이다. |

### 1.2 프로젝트에서 확인한 사실 (관찰 근거이며, 그 자체로 제품 의도는 아님)

- **제품 원본 (BRIEF.md):** "함께 배우는 AI 오목"이다. 오목 초보자용 학습 앱이며 15×15 자유 오목(금수 없음, 5목 이상 승리), 사람 흑 선공, AI 백으로 정해져 있다. 착수 전에는 추천과 이유를, 착수 후에는 평가와 예상 상대 수를 보여준다. 1440×900과 390×844 두 크기에서 조작할 수 있어야 하고, 로컬에서만 실행되며 로그인·외부 API·수집 기능이 없다.
  - BRIEF의 원문 제약: **"실제 승률을 산출·검증할 근거가 없다면 임의의 퍼센트를 승률처럼 내놓지 마세요"**. 또 "예상 수는 가능한 대응이지 확정된 미래가 아닙니다".
  - "프로 수준 탐색 엔진, 학습 DB는 초기 범위 밖"이며, "검증하지 않은 강도·교육 효과는 주장하지 말 것".
- **엔진 (src/engine.ts, Library/engine-notes.md):**
  - 즉시 승리와 유일한 방어를 먼저 고른다. 그 밖에는 후보를 12개로 제한한 2-ply minimax(`chooseMove`)를 쓴다.
  - 정적 평가 `evaluate`는 길이 5 창 572개에 1/8/64/512 가중치를 주고 ±100,000으로 자른다. 엔진 노트가 직접 "H를 승률·통계적 확신·등급으로 해석하지 않는다"고 적고 있다.
  - 결과(`Analysis`)는 수 1개, 설명 1개, 판 요약 문장 1개다. **후보 목록, 후보별 점수, 수순(PV), 확률은 바깥으로 내보내지 않는다.**
  - 엔진 버전은 `local-2ply-v1`이다. 결정적이며 난수를 쓰지 않는다.
- **비동기 구조 (analysis-client.ts, worker.ts, protocol.ts):**
  - 분석은 Web Worker 1개에서 돈다. 2초 watchdog이 걸리면 메인 스레드의 간이 분석(1-ply)으로 넘어간다.
  - 오래된 결과는 gameId, revision, requestId, key, purpose, engineVersion이 모두 일치할 때만 받아들인다.
  - `validResult`는 수 1개와 설명 구조만 검증한다.
- **흐름 (controller.ts, main.ts):**
  - 상태는 `intro → thinking(흑) → human → thinking(백) → review → [AI 응수 보기 클릭] → thinking(흑) …`, 그리고 `finished`다.
  - **AI는 사용자가 `AI 응수 보기`를 눌러야 둔다.** 학습을 위해 일부러 둔 정지 지점이다.
  - 추천은 판 위 고리 1개로, 예상 백 수는 점선 고리 1개로 표시한다.
  - 되돌리기(P4)와 종료 후 복기(P5)가 있다.
- **화면 (DESIGN.md v0.1, 사용자 시각 승인 없음):**
  - 원문 "랭킹·**승률 게이지는 두지 않는다**".
  - 데스크톱은 판 520px와 설명 350px, 모바일은 판 폭 358px 이하다. 모바일 판의 한 칸은 약 22~23px이다(work/evidence/mobile-review.png로 확인).
  - 추천, 선택, 예상, 실제 돌이 겹쳐도 라벨과 모양으로 구별한다. 색만으로 구별하지 않는다.
- **화면 문구:** 판 요약 카드에 "승률이나 최종 결과의 예측이 아닙니다"가, 도움말에 "유불리는 연결 모양에 대한 평가이며 승률이 아닙니다"가 있다. 새 기능을 넣으면 이 문구를 바꿔야 한다.
- **품질 상태 (ROADMAP, ISSUES, work/evidence/checks.txt):** P0~P5가 완료됐고 단위 테스트 62개와 E2E 18개가 통과한다. 실물 휴대폰, 저사양 성능, AI 강도, 교육 효과, 사용자 시각 승인은 확인하지 않았다.

### 1.4 Grill 활성 판단 (예비)

- Core 축은 모두 해당한다. 특히 happy_path, alternative_path, error, recovery, state, data, boundary, acceptance가 중요하다.
- **async 팩이 해당한다.** 분석 대기, 시간 초과, 재시도, 늦게 도착한 결과, 부분 결과(점진 표시), 취소를 다뤄야 한다.
- destructive-action 팩은 기존 새 게임과 되돌리기 범위에서만 해당한다. 새 파괴적 동작은 없다.
- auth, money, permission, file-upload 팩은 해당하지 않는다. 로그인, 결제, 권한, 업로드가 없다.

## 2. 사용자에게 물을 미결 결정 (우선순위 순)

질문은 한 번에 하나씩, 위에서부터 묻는다. 각 항목에 선택지와 추천안을 적었다.

### Q1. "승률"을 무엇으로 보여줄까요? (최우선이며 BRIEF와 충돌함)
- **왜 중요한가:** 엔진 방식, 계산 시간, 화면 문구, 기존 제약 유지 여부가 모두 이 답에 달려 있다.
- **선택지**
  - **A. 시뮬레이션 승률:** 각 후보 위치에서 정해진 규칙으로 끝까지 가상 대국을 N판(예: 수백 판) 두고, 흑이 이긴 비율을 "이 앱 AI끼리 둔 가상 대국 기준 승률"로 보여준다. 표본 수와 "참고용" 표시를 함께 붙인다.
    - 장점: 실제로 계산하고 재현할 수 있는 퍼센트다. BRIEF가 요구한 "산출 근거"를 갖춘다.
    - 단점: 계산이 무겁고 값이 흔들린다. 실제 사람과 둔 승률은 아니다.
  - **B. 퍼센트 없는 유불리 등급:** 각 위치를 "매우 유리 / 유리 / 비슷 / 불리 / 위험" 같은 5단계와 색으로 보여준다. "승률"이라는 말은 쓰지 않는다.
    - 장점: BRIEF를 그대로 지키고, 빠르고 안정적이다.
    - 단점: 요청한 "승률"과 다르다.
  - **C. 평가 점수를 퍼센트로 환산:** 기존 평가 점수를 곡선으로 바꿔 %처럼 보여준다.
    - 장점: 가장 쉽다.
    - 단점: 근거 없는 승률이다. BRIEF 제약을 명시적으로 폐기해야만 쓸 수 있다.
- **추천: A.** 표시 이름은 "가상 대국 승률(참고)", 표본 수를 함께 보여주고, 퍼센트는 정수로 반올림한다. 즉시 승리나 즉시 패배처럼 확정된 수는 "확정 승리 / 막지 않으면 패배"로 따로 표기한다. A를 고르면 BRIEF 제약을 지키면서 요청도 충족할 수 있다.

### Q2. AI가 언제 실제로 두게 할까요? ("실제로 작동하는 AI 대국"의 뜻)
- **선택지**
  - **A. 자동 응수:** 내가 두면 분석 표시와 함께 AI가 짧은 지연(예: 0.5~1초) 뒤 자동으로 둔다. `AI 응수 보기` 단계를 없앤다.
  - **B. 지금처럼 버튼을 눌러야 AI가 둔다:** 학습용 정지 지점을 유지한다.
  - **C. 설정으로 선택:** 기본은 자동이고, "한 수씩 멈춰 보기"를 켤 수 있다.
- **추천: C (기본은 자동).** "실제 대국"이라는 요청을 충족하면서 기존 학습 흐름도 남길 수 있다. 자동 모드에서는 AI가 둔 뒤에도 "AI가 예상했던 수 / 실제 둔 수"를 직전 수 기록으로 남긴다.

### Q3. "경우의 수"는 무엇을 보여줄까요?
- **선택지**
  - **A. 후보 수 목록:** 상위 N개 후보를 순위, 승률, 한 줄 이유와 함께 보여준다.
  - **B. A에 예상 수순 추가:** 후보마다 "내 수 → 상대 예상 → 내 다음 수"처럼 2~3수 이어지는 수순을 펼쳐 보거나 판 위에 번호로 미리 보여준다.
  - **C. 수 트리:** 후보와 상대 응수를 단계별 가지로 탐색하는 트리를 보여준다.
- **추천: B.** 후보는 3개, 수순은 3수까지로 한다. 후보를 고르면 판 위에 수순이 번호 붙은 반투명 돌로 미리 표시되고, 실제 착수와는 분명히 구별한다. C는 모바일에 들어가기 어렵고 초보자에게 과하다.

### Q4. "각 위치별" 표시 범위는 어디까지일까요?
- **선택지**
  - **A. 판 전체 히트맵:** 의미 있는 모든 빈칸에 색으로 승률을 칠한다. 숫자는 누르거나 마우스를 올렸을 때 보인다.
  - **B. 상위 후보만:** 상위 N개 위치에만 판 위에 숫자를 표시한다.
  - **C. 기본은 B, 히트맵은 켜고 끌 수 있음.**
- **추천: C.** 모바일 판의 한 칸은 약 22px이라 모든 칸에 숫자를 넣으면 읽을 수 없다. 기본 화면에는 상위 3곳의 숫자만 보여주고, "전체 보기"를 켜면 색 히트맵을 보여준다. 히트맵에서는 칸을 눌러 그 칸의 수치를 확인한다. 색만으로 구별하지 않도록 범례와 패턴을 함께 쓴다.
- 참고: 시뮬레이션 계산량 때문에 "전체"도 기존 돌 근처의 빈칸으로 제한해야 할 수 있다. 이 경우 나머지 칸은 "계산 안 함"으로 표시한다.

### Q5. 상대 예상 수는 몇 개를, 언제 보여줄까요?
- **선택지**
  - **A. 1개 (현재처럼):** 내가 둔 직후 백의 가장 유력한 대응 1곳만 보여준다.
  - **B. 여러 개:** 백의 예상 대응 상위 3곳을 "AI가 고를 가능성" 순위나 빈도와 함께 보여준다.
  - **C. 착수 전에도:** 내가 후보를 선택한 순간 "여기 두면 백은 이렇게 받을 것" 예상을 미리 보여준다.
- **추천: B와 C를 함께.** 내 후보를 선택(확정 전)하면 그 수에 대한 백의 예상 대응 상위 3곳을 미리 보여주고, 확정한 뒤에는 실제 판 기준으로 다시 계산한다. "AI가 실제로 둘 확률"이 아니라 "분석 순위"라고 표기한다.

### Q6. 기존 "함께 배우는" 학습 성격을 유지할까요?
- **선택지**
  - **A. 유지와 확장:** 문장 해설, 3단계 학습 표시, 직전 수 돌아보기를 그대로 두고, 분석 패널(후보, 승률, 예상 수)을 더한다.
  - **B. 분석 도구형으로 전환:** 해설 문장을 줄이고 수치와 시각 정보 중심의 "분석 대국" 화면으로 바꾼다. 앱 이름과 소개 문구도 바꾼다.
- **추천: A.** BRIEF의 제품 목표를 보존하고, 1순위 후보에는 기존 사실 기반 해설 문장을 그대로 붙인다. 다만 모바일 정보량은 Q4·Q8의 결정에 맞춰 줄인다.

### Q7. 분석 대기 시간은 어느 정도까지 괜찮을까요?
- **선택지**
  - **A. 빠르게 (약 1초 이내):** 표본 수가 적어 승률이 덜 정확하다.

### Q9. AI 상대의 강도를 바꿀 수 있게 할까요?

## 3. 담당자가 정할 비중요 결정

다음은 국소적이고 되돌리기 쉬운 결정이라 담당자가 정하고 기록만 한다. 위 미결 답에 따라 일부 값은 조정한다.

- **시뮬레이션 구현:**
  - 가상 대국 규칙은 즉시 승리 → 유일 방어 → 근처 후보 가중 무작위로 둔다. 판당 착수 수에 상한을 두고, 상한에 닿으면 무승부로 처리한다.
  - 시드를 고정한 의사난수를 써서 같은 판과 같은 설정이면 같은 결과가 나오게 한다(테스트 재현성).
  - 후보별 표본 수 배분과 반올림 규칙(정수 %)을 정한다.
  - 즉시 승리나 즉시 패배 위치는 시뮬레이션 대신 확정값으로 덮어쓴다.
- **후보 생성:** 기존 `candidates`/`rankedNearby`(체비쇼프 거리 2, 12개)를 재사용할지, 히트맵용으로 범위를 넓힐지 정한다. 계산하지 않은 칸은 "계산 안 함"으로 표기한다.
- **프로토콜:**
  - `Analysis`에 후보 목록(좌표, 승률, 표본 수, 수순), 예상 응수 목록, 히트맵 맵을 더한다.
  - `ENGINE_VERSION`을 올리고 `validResult`에 새 필드 검증을 더한다. 오래된 결과를 거르는 식별자 규칙은 유지한다.
  - 점진 결과에는 같은 requestId 안의 순번을 붙이고, 마지막 확정 결과를 따로 표시한다.
- **Worker 수명:** 점진 계산 중 새 착수, 되돌리기, 새 게임이 일어나면 terminate하고 다시 만든다. watchdog 상한을 다시 정하고, 폴백은 기존 간이 분석에 "승률 계산 불가" 표시를 붙인다.
- **AI 응수 선택:** 자동 응수에서 AI가 쓰는 수는 기존 `chooseMove` 결과로 둔다(결정적). 시뮬레이션 1순위와 다를 수 있으며, 이때 "예상 순위"라는 표기로 설명한다.
- **시각 표현 세부:**
  - 히트맵 색 계열(색각 이상 대비 단일 색상 명도 단계와 패턴), 후보 순위 배지 모양, 수순 미리보기 돌의 투명도와 번호 글꼴.
  - 기존 추천 고리와 예상 점선 고리와 겹치지 않게 하는 규칙.
- **문구 정리:** "승률이 아닙니다" 문구를 결정된 의미에 맞게 고친다. 도움말에 계산 방법과 한계 1단락을 추가한다.
- **접근성:**
  - 각 교차점의 aria-label에 "추천 2위, 가상 승률 54%" 같은 정보를 붙인다.
  - 후보 목록은 키보드로 고를 수 있게 하고, live 알림은 "분석 완료" 1회로 제한한다. 225칸 숫자를 읽어 주지 않는다.
- **동작 감소 설정:** 점진 갱신 때 숫자 깜빡임을 막는다. 자동 응수 지연 애니메이션은 감소 설정에서 생략한다.
- **테스트:**
  - 시뮬레이션 결정성, 확정 승패 덮어쓰기, 후보와 수순의 합법성, 오래된 점진 결과 거절, 자동 응수 1회 보장(중복 돌 없음), 두 지정 화면의 렌더와 조작.
  - 성능 smoke로 중반 판 20개의 분석 시간을 측정한다.
- **문서 갱신 위치:** ROADMAP에 새 단계 P6, TASK 기록, DESIGN 제안 v0.2, Library/engine-notes 시뮬레이션 절. BRIEF는 보존하고, 사용자 결정이 BRIEF 제약을 바꾸면 그 결정을 ROADMAP 범위 표에 출처와 함께 기록한다.

### 4.2 최소 화면(390×844) 정보 배분

- **스크롤 없이 한 화면에 보여야 할 것:**
  - 판과 그 위의 상위 3 후보 배지(숫자 포함), 선택한 칸.
  - 행동 영역(선택 좌표, 두기 버튼, 분석 상태 1줄).
  - 현재 형세 1줄(내 가상 승률).
  - 기존 헤더와 제목을 줄여야 할 수 있다. 큰 제목 2줄은 축소하는 방향을 담당자가 검토한다.
- **펼침이나 스크롤 아래에 둘 것:** 후보 목록의 이유 문장, 상대 예상 수 상세, 직전 수 기록, 한계 안내.
- **기본에서 빼고 켜야 보이는 것:** 판 전체 히트맵(칸을 누르면 그 칸의 수치를 판 아래 1줄로 보여준다), 수순 미리보기(후보의 "수순 보기"를 눌렀을 때만).
- 판 칸 위에 숫자를 넣는 것은 상위 3곳만이다. 약 22px 칸에 2자리 숫자와 % 기호를 넣기 어려우면, 판 위에는 순위 배지(1·2·3)만 두고 숫자는 행동 영역 아래 한 줄 칩("1 H8 58% · 2 J9 52% · 3 G7 49%")으로 보여준다. 이 대안은 Q4 확정 후 디자인 검증에서 고른다.

### 4.3 입력 방식

- **선택과 확정:** 기존과 같다. 교차점을 누르거나 클릭하면 선택되고, 좌표 버튼으로 확정한다. 키보드는 Tab으로 판에 들어가 방향키로 움직이고 Enter로 선택한다.
- **후보 고르기:** 분석 패널이나 칩의 후보를 누르면 그 칸이 선택된다. 착수는 하지 않는다. 기존 `추천 위치 선택`을 확장한 동작이다.
- **선택이 바뀔 때:** 그 후보에 대한 백 예상 대응 3곳을 다시 보여준다. 이미 계산한 값이면 즉시, 아니면 "계산 중"을 표시한다.
- **수순 미리보기:** "수순 보기"를 누르면 판에 번호 돌이 표시된다. 다시 누르거나 다른 칸을 선택하면 사라진다. 착수에는 영향을 주지 않는다.
- **히트맵:** 스위치로 켜고 끈다. 켜진 상태에서 칸을 누르면 그 칸을 선택하면서 수치 1줄을 보여준다. 기존 선택 절차를 바꾸지 않는다.
- **마우스 hover:** 데스크톱에서만 툴팁으로 수치를 보여주는 보조 수단이다. 터치에서는 hover에 의존하지 않는다.

### 4.4 사용자 흐름 (자동 응수 기본, 분석 보조 켜짐)

1. **첫 진입:** 소개 카드에서 "AI와 대국하며, 각 수의 후보·가상 승률·상대 예상 수를 볼 수 있어요. 승률은 이 앱 AI끼리의 가상 대국 결과입니다."를 읽고 `첫 게임 시작`을 누른다.
2. **내 차례 분석:**
   - 흑 분석이 시작되고 "계산 중 · 표본 n판"이 표시된다. 약 1초 안에 상위 3 후보와 대략적인 승률이 나타나고, 최대 약 3초 동안 숫자가 갱신된 뒤 "분석 완료"가 된다.
   - 계산 중에도 칸을 선택할 수 있다. 착수 확정은 계산 중에도 허용할지 여부를 담당자가 비동기 계약으로 정한다. 허용하면 진행 중인 분석은 취소한다.
3. **후보 검토:** 후보나 칸을 선택하면 해당 백 예상 대응 3곳이 점선 고리로 보인다. 필요하면 "수순 보기"를 누른다.
4. **확정:**
   - `H8에 두기`를 누르면 흑 돌이 놓이고, 직전 수 기록에 내 수 평가(기존 사실 기반 해설)가 남는다.
   - 착수 직후의 내 형세 승률을 보여준다. 이전 판과의 차이를 표시할지는 담당자가 결정하되, 다른 표본에서 나온 값의 차이라는 점을 밝힌다.
5. **AI 응수 (자동):**
   - "백이 생각 중"을 표시하고 약 0.5~1초 뒤 백 돌이 놓인다.
   - 직전 수 기록에 "예상 1위 J8 · 실제 J8"처럼 예상과 실제를 함께 남기고, 2번으로 돌아간다.
   - "한 수씩 멈춤" 모드라면 기존처럼 `AI 응수 보기`를 눌러야 둔다.
6. **종료:** 승패나 무승부, 승리선을 보여주고 분석 표시를 모두 지운다. `대국 복기`와 `새 게임`이 있다. 복기 화면은 Q10 결정에 따른다.
- **실수와 회복:**
  - 잘못 선택한 칸은 다른 칸을 눌러 바꾼다. 잘못 둔 수는 `되돌리기`로 되돌린다. 백이 자동으로 이미 뒀다면 내 수와 백 수를 함께 취소한다(기존 계약).
  - 분석이 실패하거나 시간을 넘기면 판은 그대로 두고, "간이 분석 · 승률 계산 안 됨"과 `다시 분석하기`를 보여준다. 이때 후보 1곳만 보여주고 승률 숫자는 숨긴다. 가짜 숫자는 만들지 않는다.
  - 분석 보조를 끄면 판 위 분석 표시가 모두 사라지고 대국만 계속된다. 다시 켜면 현재 판을 새로 분석한다.
- **다시 방문:** 저장 기능이 없어 새로고침하면 판과 설정이 초기화된다(기존 원칙 유지, 도움말에 안내).

| 상태 | 판/패널 표시 |
| --- | --- |
| 기본 (분석 완료) | 후보 3개, 승률, 예상 수, 형세 |
| 로딩 (계산 중) | 기존 값은 지우고 "계산 중" 표시. 점진 값이 오면 "표본 n판, 갱신 중" 표시 |
| 부분 결과 | 점진 결과가 1차로 도착한 상태. 숫자 옆에 "갱신 중" 표시 |
| 시간 초과/오류 | 간이 분석과 승률 숨김, 재시도 버튼 |
| 확정 결과 | 즉시 승리나 즉시 방어 칸은 % 대신 "바로 승리" / "꼭 막아야 함" 라벨 |
| 비활성 | 내 차례가 아닐 때, 복기 중, 종료 후에는 후보와 히트맵을 숨기고 판 선택을 막음 |
| 분석 끔 | 판과 행동 영역만 표시 |
| 취소됨 | 새 착수, 되돌리기, 새 게임으로 진행 중이던 분석을 폐기. 늦게 온 결과는 무시 |
| 해당 없음 | 권한 거부, 미인증, 만료 (계정 없음). 오프라인은 로컬 앱이라 영향 없음 |

### 4.6 수용 기준 초안 (확정 전)

- 표시된 모든 후보, 예상 수, 수순은 현재 판에서 합법이고, 요청 식별자가 현재 판과 일치한다.
- 승률 숫자는 계산 근거(가상 대국 표본 수)를 화면이나 도움말에서 확인할 수 있다. 계산하지 못한 경우 숫자를 표시하지 않는다.
- 자동 응수는 한 차례에 백 돌을 정확히 1개만 놓는다. 되돌리기, 새 게임, 늦게 온 결과와 섞여도 마찬가지다.
- 1440×900과 390×844에서 판, 후보 배지, 행동 버튼, 형세 1줄이 스크롤 없이 보이고 조작할 수 있다.
- 기존 규칙, 되돌리기, 복기 회귀 테스트가 통과한다. AI 강도, 승률의 실제 정확도, 교육 효과는 "미검증"으로 표기한다.
