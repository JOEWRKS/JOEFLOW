# JOEFLOW 1.7.2

1.7.1 게시 뒤 행동 시험(8회)에서 찾은 `projection_check.py` 오탐 하나를 고쳤습니다. State 0.2.0, 고정 검증 모듈, 바인딩 계약, 기존 승인은 그대로입니다. 상세: [보고서](https://github.com/JOEWRKS/JOEFLOW/blob/main/evals/2026-11-15-stale-title-172/report.md).

## 바뀐 것

- **오탐 수정**: 투영 문서 머리 영역의 "마지막 승인은 revision 1입니다", "마지막으로 승인된 것은 revision 1이다", "revision 1만 승인됨", "last approved: rev 1" 같은 승인 상태 서술 문장은, 그 숫자가 state의 마지막 승인 revision과 같을 때 낡은 제목으로 지적하지 않습니다. 1.7.1은 이를 `stale_spec_title_revision`(기대 2·실제 1)으로 잡았습니다. 꾸밈말 없는 "승인 revision 1", "Approved: rev 1"은 낡은 제목과 글자로 구별이 안 돼 여전히 검출합니다. 숫자가 마지막 승인 revision과 다른 승인 문장은 틀린 문장이라 검출합니다.
- **next_action 안전 문장**: 제목·머리가 문서 자신의 revision을 적은 줄이면 손으로 고치고, 다른 revision(이전·마지막 승인)을 사실대로 적은 문장이면 고치지 말고 검사기 오탐으로 보고하라고 안내합니다.
- `references/workflow-v0.2.0.md`에 바뀐 범위 한 줄. 출력 JSON 모양은 그대로입니다.

## 확인된 것

- 행동 시험 r1·r6의 실제 문서로 1.7.1 오탐을 재현(시험 당시 저장 결과와 동일)하고 후보에서 사라짐. 8개 run 문서 모두 ok true.
- 마지막 승인 번호를 쓴 낡은 손제목 7형, 틀린 승인 문장은 여전히 검출(새 테스트 5건). 1.7.1 제목 테스트 7건 그대로 통과.
- 전체 1,256개 중 실패·오류 8건은 1.7.1과 같은 환경 원인 목록. AI-Gomoku rev 44 실제 투영(읽기 전용 사본) 출력이 1.7.1과 바이트 단위로 같음.

## 확인되지 않은 것

- 새 next_action 문장을 받은 에이전트가 사실 문장을 그대로 두고 진짜 낡은 제목만 고치는지(행동 시험 0회).
- "revision 1이 승인된 마지막 판이다", "1번째 승인" 같은 어순·표기, 앞 30자 창을 넘는 긴 삽입구는 덮지 않습니다.
- 영어 승인 문장은 실제 문서에서 나온 적이 없어 직접 만든 문장으로만 시험했습니다.

## 세션이 대신 내린 결정

1. 숫자 조건(마지막 승인 revision과 같을 때만 건너뜀)을 추가. 틀린 승인 문장을 놓치지 않기 위해서입니다.
2. 꾸밈말 없는 "승인 revision N"류는 제외 범위에 넣지 않음.
3. next_action 안전 문장 추가.
