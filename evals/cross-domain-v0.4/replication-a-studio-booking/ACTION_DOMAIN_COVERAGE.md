## Handler classification

Every visible action enters `app.handle()`, which calls `executeAction(..., payload.confirmed=false)`. The dispatcher has only four action-specific mutations:

- `create_resource` appends one hard-coded equipment object;
- `create_resource_block` appends one hard-coded room block;
- `mark_equipment_unavailable` sets one hard-coded camera outage flag;
- `sign_in_operator` sets a minimal active session.

Six destructive actions stop at `CONFIRMATION_REQUIRED` because the SPA has no confirmation continuation: `deactivate_operator`, `release_legal_hold`, `withdraw_policy_version`, `deactivate_resource`, `release_resource_block`, and `mark_booking_no_show`. Every other authorized action appends only `{action, role, at, payload}` to a generic audit array and advances the version.

For the 66 mutating/workflow actions, the result is therefore:

| --- | ---: |
| Canonical mutation partially implemented | 4 |
| Confirmation guard with no reachable continuation | 6 |
| Canonical mutation replaced by generic audit append | 56 |

## Determination

The dominant failure is a **systematic UI → domain disconnect**, not a small set of isolated missing handlers.

- Handoff ambiguity is not the cause: the handoff names all 27 screens, 78 actions, high-fan-out invariants, and nine required observable scenarios.
- The implementation agent simplified most actions into one generic success/audit path and built richer helper functions without connecting them to the SPA.
- The evaluator/test blind spot allowed inventory, labels, source tokens, and direct helper tests to stand in for rendered state-transition coverage.
- Artifact-specific omissions—hours/outages, snapshots, management drafts, lifecycle, incidents, attendance—are broad consequences of that architectural simplification.
- Pass 3 made the disconnect more systematic by routing the SPA uniformly through `executeAction`, reopening delivery finding `A-CODEX-DRIFT-006` while leaving the action-specific helper behavior unreachable.
