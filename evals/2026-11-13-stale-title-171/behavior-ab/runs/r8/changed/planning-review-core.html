요청 폼 기획 검토 (revision 2)

로그인한 요청자가 유효한 요청을 제출하는 폼. rev 2에서 요청 내용 칸의 글자 수 표시를 더했습니다.

이 문서는 기획의 축약 시각본입니다. 제품 UI 시안이나 visual-design authority가 아니며, 기준은 state.json입니다.

범위IA흐름 화면정책상태

제품과 범위

  • 목표 GOAL-001: 요청자가 유효한 요청 제출을 끝낸다.
  • 사용자 USR-001: 로그인한 요청자.
  • 요구사항 REQ-001: 유효한 요청을 제출할 수 있다.
  • 연동 INT-001: Request API가 수락된 요청을 저장한다.
  • rev 2 추가: 글자 수 표시 추가 (DEC-002, RULE-002, AC-002, TASK-002)

IA와 이동 관계

화면은 하나이며, 다른 화면으로의 이동은 정의되어 있지 않습니다.

핵심 User Flows

FLOW-001. 상세 조건은 Master의 stable ID로 연결합니다.

검증 실패 시 화면 반응(메시지 등)은 state.json에 정의되어 있지 않습니다.

화면 요약

SCR-001 요청 제출

요청을 제출한다. 동작: submit. 필수 입력이 유효할 때(STATE-001)만 제출.

요청 내용 textarea(최대 200자). 칸 아래 오른쪽에 '현재 글자 수 / 200', 빈 칸은 '0 / 200'. rev 2

중요 정책과 제한

  • RULE-001 유효한 요청만 제출할 수 있다 (DEC-001).
  • RULE-002 글자를 넣거나 지울 때마다 '현재 글자 수 / 200'을 바로 바꾼다 (DEC-002, AC-002). 추가
  • 요청 내용은 최대 200자(EVD-902).
  • 열린 질문 없음 (UNK-001, UNK-002 RESOLVED).
