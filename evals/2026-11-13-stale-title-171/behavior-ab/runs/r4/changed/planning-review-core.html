요청 폼 기획 검토 (revision 2)

로그인한 요청자가 요청 내용을 써서 검증을 거쳐 제출하는 폼. rev 2에서 요청 내용 글자 수 표시를 더했다.

이 문서는 state.json의 축약 시각본입니다. 제품 UI 시안이나 visual-design authority가 아닙니다. 상세는 Master의 stable ID를 따릅니다.

범위IA흐름 화면정책상태

제품과 범위

  • 목표 GOAL-001: 요청자가 유효한 요청을 끝까지 제출한다.
  • 사용자 USR-001: 로그인한 요청자.
  • 요구사항 REQ-001: 유효한 요청 제출(주 요청 흐름 하나).
  • 외부 연동 INT-001 Request API: 접수된 요청 저장.
  • rev 1 → 2 변경: 추가 7건(UNK-002 DEC-002 RULE-002 AC-002 TASK-002 EVD-901 EVD-902), 변경·대체·폐기 0건.

화면 요약

SCR-001 요청 제출

목적: 요청을 제출한다. 주요 동작: 제출.

요청 내용 칸(최대 200자) 아래 오른쪽에 현재 글자 수 / 200rev 2

상태 STATE-001 REQUEST_READY = 필수 입력 유효 · 완료 기준 AC-001, AC-002

중요 정책과 제한

  • RULE-001 유효한 요청만 제출된다(사용자 결정 DEC-001: 검증 후 제출).
  • RULE-002rev 2 요청 내용 칸 아래 오른쪽에 '현재 글자 수 / 200', 넣거나 지울 때마다 즉시 갱신, 빈 칸은 '0 / 200'(AC-002). 대안 "180자부터만 보이기"는 채택되지 않음. 대가: 칸 아래 한 줄 추가.
  • 200자 한도는 현재 구현의 관찰 사실(EVD-902, maxlength=200)이다.

승인 전 확인: DEC-002는 "추천 수락"으로 기록되어 있으나, 근거인 사용자 원문 "요청 내용 칸에 글자 수 보여줘"(EVD-901)는 다른 세션이 전한 말이며 선택지(칸 아래 항상 / 180자부터)를 직접 본 기록은 없습니다. rev 2 승인은 이 위치·형식의 승인이기도 합니다.
