요청 폼 기획 검토 (revision 2)

로그인한 요청자가 유효한 요청을 제출하는 요청 폼. revision 2는 요청 내용 칸의 글자 수 표시를 더한다.

이 문서는 승인 대기 중인 revision 2 기획의 축약 시각본입니다. 정본은 state.json이며, 제품 UI 시안이나 visual-design authority가 아닙니다.

범위IA흐름 화면정책상태

제품과 범위

  • 사용자: 로그인한 요청자 (USR-001)
  • 목표: 요청자가 유효한 요청을 끝까지 제출한다 (GOAL-001)
  • 요구사항: 요청자는 유효한 요청을 제출할 수 있다 — 범위는 기본 요청 흐름 하나 (REQ-001, SURF-001 Request submission)
  • 데이터·연동: 요청 입력(DATA-001, 요청자 소유)을 Request API(INT-001)가 수락 시 저장
  • revision 1→2 변경: 추가 7건(EVD-901, EVD-902, UNK-002, DEC-002, RULE-002, AC-002, TASK-002), 변경·대체·폐기 0건

IA와 이동 관계

정보 계층과 실제 화면 이동을 구분해 표시합니다.

정본에 정의된 화면은 SCR-001 하나뿐입니다. 제출 뒤 이동할 화면이나 되돌아가기 경로는 정의되어 있지 않습니다.

핵심 User Flows

주요 정상·실패·복구 분기를 표시합니다. 상세 조건은 Master의 stable ID로 연결합니다.

  1. FLOW-001 요청 제출 — 전제: 요청자가 로그인되어 있다. 진입: 요청 폼을 연다.
  2. 요청 내용을 입력한다. 입력하거나 지울 때마다 칸 아래 오른쪽에 현재 글자 수 / 200이 바로 바뀐다(빈 칸은 0 / 200) rev 2 (RULE-002, AC-002)
  3. 시스템이 제출 전에 요청을 검증한다 (DEC-001, RULE-001). 필수 입력이 유효하면 REQUEST_READY 상태(STATE-001).
  4. 성공: 유효한 요청이 수락되어 저장된다 (AC-001).
  5. 유효하지 않은 요청: 제출되지 않는다 (RULE-001). 거부 시 보이는 문구·복구 방법은 정본에 정의되어 있지 않습니다.

화면 요약

SCR-001 요청 폼

목적: 요청을 제출한다. 주요 동작: 제출(submit).

요청 내용 칸: textarea 하나, 최대 200자(EVD-902, 현재 구현 관찰). 칸 아래 오른쪽에 글자 수 현재 / 200이 항상 보인다 rev 2.

중요 정책과 제한

  • RULE-001 유효한 요청만 제출할 수 있다 (사용자 결정 DEC-001: 제출 전 검증).
  • RULE-002 rev 2 요청 내용 칸 아래 오른쪽에 '현재 글자 수 / 200'을 보이고, 넣거나 지울 때마다 바로 바꾼다 (DEC-002).
  • 200자 한도는 기존 구현에서 관찰한 사실(EVD-902)이며 이번 revision이 바꾸지 않는다.

승인 전에 확인할 점

  • DEC-002는 전달받은 사용자 원문 "요청 내용 칸에 글자 수 보여줘"(EVD-901, 다른 세션 전달)를 추천안 BELOW(항상 표시) 수락으로 기록했습니다. 원문은 위치·표시 시점(항상 vs 180자부터)을 직접 고르지 않았으므로, 이 화면에서 '항상 표시'가 의도와 맞는지 확인해 주세요. 다른 선택지: 180자부터만 표시(NEAR_LIMIT).
