요청 폼 기획 검토 (revision 2)

로그인한 요청자가 요청 내용을 적고, 검증을 통과한 요청만 제출해 저장하는 폼입니다. revision 2에서 요청 내용 칸에 글자 수 표시가 추가되었습니다.

이 문서는 state.json과 Master를 줄인 검토용 시각본입니다. 제품 UI 시안이나 visual-design authority가 아닙니다.

범위IA흐름 화면정책상태

제품과 범위

  • 목표 GOAL-001: 요청자가 유효한 요청을 끝까지 제출한다.
  • 사용자 USR-001: 로그인한 요청자.
  • 요구사항 REQ-001: 유효한 요청을 제출할 수 있다. 표면 SURF-001 IN_SCOPE.
  • 범위 밖(EVD-900): 결제, 파일 업로드, 비동기 처리, 권한 구분, 파괴적 작업.

IA와 이동 관계

화면은 하나입니다. 제출 후 이동할 화면은 정의되어 있지 않습니다.

핵심 흐름 FLOW-001

정상 경로와 거부 분기만 표시합니다. 상세 조건은 Master의 stable ID를 따르세요.

거부 뒤 복구 방식(오류 문구, 입력 유지)과 제출 후 다음 화면은 정의되어 있지 않습니다.

화면 요약

SCR-001 요청 폼

목적: 요청을 제출한다. 주요 동작: 제출.

요청 내용 칸: textarea 하나, 최대 200자 (EVD-902, 구현 관찰).

글자 수 표시rev 2: 칸 아래 오른쪽 '현재 글자 수 / 200', 입력·삭제마다 즉시 갱신, 항상 보임. 빈 칸은 '0 / 200' (RULE-002, AC-002).

중요 정책과 제한

  • RULE-001 / DEC-001: 유효한 요청만 제출할 수 있다 (사용자 결정).
  • RULE-002 / DEC-002rev 2: 요청 내용 칸 아래 오른쪽에 '현재 글자 수 / 200'을 입력할 때마다 바로 보인다. 다른 안(180자부터만 표시)은 선택되지 않음. 대가: 칸 아래 한 줄이 늘어난다.
  • "유효함"의 구체 항목은 정의되어 있지 않습니다.

확인 권장: DEC-002는 다른 세션이 전달한 사용자 원문 "요청 내용 칸에 글자 수 보여줘"(EVD-901)를 추천안 수락으로 기록했습니다. 원문이 위치를 직접 고르지는 않았으니 승인할 때 위치와 '항상 보임'을 확인해 주세요.
