요청 폼 기획 검토 (revision 2)

로그인한 요청자가 요청 내용을 적고, 검증을 통과한 요청만 제출하는 폼. rev 2는 요청 내용 칸에 글자 수 표시를 더한다.

이 문서는 state.json의 축약 시각본입니다. 제품 UI 시안이나 visual-design authority가 아닙니다. 다르면 state.json이 맞습니다.

범위IA흐름 화면정책상태

제품과 범위

  • 목표 GOAL-001: 요청자가 유효한 요청을 끝까지 제출한다.
  • 사용자 USR-001: 로그인한 요청자.
  • 요구사항 REQ-001: 유효한 요청을 제출할 수 있다.
  • rev 2 추가NEW: 요청 내용 칸 아래 오른쪽에 현재 글자 수 / 200 표시 (DEC-002 · RULE-002 · AC-002 · TASK-002).
  • 범위 밖(EVD-900): 결제, 파일 업로드, 비동기 처리, 역할별 권한, 파괴적 동작.

IA와 이동 관계

정보 계층과 실제 화면 이동을 구분해 표시합니다.

화면은 SCR-001 하나입니다. 제출 후 이동할 화면은 승인 대상 state에 정해져 있지 않습니다.

주요 정상·실패·복구 분기를 표시합니다. 상세 조건은 Master의 stable ID로 연결합니다.

화면 요약

SCR-001 요청 폼

목적: 요청 제출. 주요 동작: submit.

상태 STATE-001 REQUEST_READY: 필수 입력이 유효할 때.

rev 2 요청 내용 칸 아래 오른쪽에 현재 글자 수 / 200, 입력·삭제마다 즉시 갱신, 빈 칸은 0 / 200 (AC-002).

중요 정책과 제한

  • RULE-001: 유효한 요청만 제출할 수 있다(DEC-001, 사용자 결정).
  • RULE-002NEW: 요청 내용 칸 아래 오른쪽에 현재 글자 수 / 200을 보이고, 글자를 넣거나 지울 때마다 바로 바꾼다(DEC-002).
  • 상한 200자는 현재 구현에서 관찰한 사실이다(EVD-902, maxlength=200).

승인 전에 확인해 주세요 — 글자 수 배치(UNK-002 / DEC-002)

이 배치는 "추천 수락"으로 기록돼 있지만, 남아 있는 사용자 말(EVD-901, 다른 세션이 전한 말)은 "요청 내용 칸에 글자 수 보여줘"뿐입니다. 아래 두 안을 보고 고른 기록은 없습니다.

  • BELOW (기록된 안): 칸 아래 오른쪽에 항상 n / 200. 대가: 칸 아래 한 줄이 늘어남.
  • NEAR_LIMIT: 180자부터만 표시. 평소엔 안 보임.

rev 2를 승인하면 BELOW로 확정됩니다. 다른 안을 원하면 승인하지 말고 다시 열어 주세요.
