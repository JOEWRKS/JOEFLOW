요청 폼 기획 검토 (revision 2)

로그인한 요청자가 요청 폼에서 유효한 요청을 제출한다. revision 2는 요청 내용 칸에 글자 수 표시를 더한다.

이 문서는 state.json revision 2(승인 대기)의 축약 시각본입니다. 제품 UI 시안이나 visual-design authority가 아니며, 내용이 다르면 state.json이 우선합니다.

범위IA흐름 화면정책확인할 점상태

제품과 범위

  • 목표 GOAL-001 — 요청자가 유효한 요청 제출을 마친다.
  • 사용자 USR-001 — 로그인한 요청자(REQUESTER).
  • 요구사항 REQ-001 — 요청자는 유효한 요청을 제출할 수 있다(주 요청 흐름, UI 있음).
  • 범위 안 SURF-001 요청 제출 기능 영역. 범위 밖: 결제·파일 업로드·비동기 처리(EVD-900, 사용자가 해당 없음으로 확인).
  • 연동 INT-001 요청 API — 접수된 요청을 저장. 데이터 DATA-001 Request — 요청 입력을 담음(소유: 요청자).

IA와 이동 관계

정보 계층과 실제 화면 이동을 구분해 표시합니다. 이 기획에는 화면이 하나(SCR-001)뿐이며, 다른 화면으로의 이동·복귀는 기획에 정의되어 있지 않습니다.

핵심 User Flows

주요 정상·실패 분기를 표시합니다. 상세 조건은 Master의 stable ID로 연결합니다.

  • FLOW-001 진입: 요청 폼 열기 · 전제: 로그인 상태 · 경로: 검증 후 제출 · 결과: 요청 접수(AC-001).
  • 유효하지 않은 요청은 제출되지 않는다(RULE-001, DEC-001). 이때의 오류 문구·복구 방법은 기획에 따로 정의되어 있지 않습니다.

중요 정책과 제한

  • RULE-001 유효한 요청만 제출할 수 있다(DEC-001 — 사용자가 '검증 후 제출'을 선택, UNK-001).
  • RULE-002 rev 2 추가 요청 내용 칸 아래 오른쪽에 '현재 글자 수 / 200'을 보이고, 글자를 넣거나 지울 때마다 바로 바꾼다(DEC-002, UNK-002).
  • 200자 한도는 현재 구현(src/index.html의 maxlength=200)을 관찰한 사실(EVD-902)에서 왔습니다.

승인 전에 확인할 점

글자 수의 위치와 표시 시점(UNK-002 → DEC-002)은 추천안 BELOW('칸 아래 오른쪽, 입력 중 항상 보임')로 정해져 있습니다. 근거로 남은 사용자 원문은 다른 세션이 전달한 "요청 내용 칸에 글자 수 보여줘"(EVD-901, 질문 "요청 폼에 더하고 싶은 것이 있나요?"에 대한 답)뿐이며, 이 말은 위치나 대안(180자부터만 보임, NEAR_LIMIT)을 고르지 않습니다.

이 revision을 승인하면 BELOW를 확정하는 것입니다. NEAR_LIMIT이나 다른 위치를 원하면 승인하지 말고 알려 주세요. 새 revision으로 고칩니다.
