요청 폼 기획 검토 (revision 2)

로그인한 요청자가 요청 내용을 입력하고, 검증을 통과한 요청만 제출·저장되는 요청 폼. rev 2에서 요청 내용 칸의 글자 수 표시를 더했습니다.

이 문서는 승인 대상 기획의 축약 시각본입니다. 제품 UI 시안이나 visual-design authority가 아닙니다. 정본은 state.json입니다.

범위IA흐름 화면정책상태

제품과 범위

  • 목표 GOAL-001: 요청자가 유효한 요청 제출을 끝낸다.
  • 사용자 USR-001: 로그인한 요청자(역할 하나).
  • 요구사항 REQ-001: 유효한 요청을 제출할 수 있다.
  • 연동 INT-001 Request API: 수락된 요청 저장.
  • rev 2 추가NEW: 요청 내용 칸 글자 수 표시 (DEC-002, RULE-002, AC-002, TASK-002).
  • 해당 없음(EVD-900): 결제, 파일 업로드, 비동기, 권한 구분, 파괴적 동작.

IA와 이동 관계

정보 계층과 실제 화면 이동을 구분해 표시합니다. 화면은 SCR-001 하나입니다.

수락 뒤 이동할 화면·돌아가기는 정의되어 있지 않습니다.

화면 요약

SCR-001 요청 화면

목적: 요청 제출. 주요 동작: submit.

제출 가능: REQUEST_READY(필수 입력 유효, STATE-001).

글자 수NEW: 요청 내용 칸 아래 오른쪽 '현재 글자 수 / 200', 넣거나 지울 때마다 즉시 갱신, 빈 칸은 '0 / 200' (RULE-002, AC-002).

중요 정책과 제한

  • RULE-001 / DEC-001: 유효한 요청만 제출할 수 있다(제출 전 검증).
  • RULE-002 / DEC-002NEW: 글자 수는 입력 중 항상 보인다(180자부터만 보이는 안은 채택 안 함). 대가: 칸 아래 한 줄 증가.
  • 제한: 요청 내용 textarea 최대 200자(EVD-902, 관찰된 구현).
  • 열린 제품 질문 없음(UNK-001, UNK-002 RESOLVED).
