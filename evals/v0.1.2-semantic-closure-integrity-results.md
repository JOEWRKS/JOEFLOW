# v0.1.2 Semantic Closure Integrity Results

## Changed

The canonical v0.1.2 contract now defines strict closure evidence, active-versus-historical semantics, screenless and non-interactive products, authoritative screen action inventories, typed graph edges, and a single full schema at `skills/joewrks-product-definition/schemas/state.schema.json`.

- `CURRENT` and `STALE` are active; `SUPERSEDED` is historical and requires an existing same-type replacement.
- Minimum closure requires an active goal, active material requirement, and active acceptance criterion; screens and UX coverage are conditional on actual UI/interactivity.
- Escape-hatch evidence is status-specific, user acceptance cannot be attributed to an agent, and deferral requires eight explanatory impact strings.

## RED Evidence

Before the implementation, all 12 new aggregate semantic regression tests failed. The observed false positives included evidence-free closed unknowns/decisions, agent self-acceptance, boolean-only deferral impact, missing action inventory entries, duplicate UX rows, invalid typed edges, and actionless screens without a reason. The observed false negatives included a valid API-only product and historical requirements/screens creating current completeness obligations. The schema test also found the old wrapper/schema shape mismatch.

## Verification

- `python -m unittest discover -s tests -v`: 40 tests run, 40 passed.
- Skill quick validation: `Skill is valid!`.
- `python -m py_compile` for `state_validation.py`, `validate_state.py`, and `validate_closure.py`: exit 0.

- Residual contract scan: no `v0.1.1` or JSON `0.1.1` references remain in README, skill resources, tests, templates, or fixtures.
