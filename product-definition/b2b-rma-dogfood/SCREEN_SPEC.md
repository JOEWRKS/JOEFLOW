- `DEC-023`에 따라 `RETURN_TO_CUSTOMER`에는 공급사 주선·거래처 운송비 부담을 표시하고 운송사·운송장 번호 또는 직접 인수 참조, 발송·배송 중·배송 완료·예외 상태와 각 시각을 기록·공개한다. 배송 완료 또는 서명·수령 확인 전에는 완료할 수 없고 분실·파손·배송 실패·미인수는 예외로 유지한다. `DEC-030`에 따라 현재 케이스 오너 RMA Agent가 이 `RETURN_TO_CUSTOMER` 반환 운송장 생성·발송 인계·직접 인수 증거·추적 갱신을 모두 직접 수행·기록하며 별도 실행 역할을 두지 않는다. `DEC-062`에 따라 운송사 배송은 거래처 수취 착불이고, 현재 오너의 실물 인계 뒤 carrier simulation 운송 접수 성공과 함께 결과 배분·부분 수량 범위별 `KRW` 운임을 확정해 포털에 금액·착불 상태를 공개한다. 라벨 값은 확정 금액이 아니며 착불 회수 성공과 배송 완료를 하나의 성공 사건으로 표시한다. 회수 실패는 배송 완료로 표시하지 않고 `DEC-050` 배송 실패·미인수 연결 정정 범위로 보낸다. 이는 최종 결과 결정 뒤 거래처로 보내는 outbound 반환 실행에만 적용하고, 승인 뒤 공급사로 회수하는 inbound 운송장의 `DEC-031` 회수 방식별 등록·갱신 책임과 혼합하지 않는다. 이 outbound `RETURN_TO_CUSTOMER` 문맥에서는 창고 담당자 쓰기 행동을 제공하지 않으며 현재 오너가 직접 실행한다. 창고 담당자의 별도 `REPLACEMENT` 출고 쓰기 범위는 `DEC-074`, 입고·검수와 `NO_CREDIT` 물리 쓰기 범위는 각 해당 전문 계약을 따른다. `DEC-063`에 따라 원 주문 납품처 주소·수령 연락처를 자기 조직 포털 기본값으로 제시하고 거래처의 확인 또는 대체 값 요청 뒤 현재 오너가 운송사 인계 전에 사용할 목적지·연락처 스냅샷을 확정하며 원 fixture와 감사 계보를 보존한다. 실제 외부 결제·청구 연동이나 직접 인수 비용은 표시·행동으로 추가하지 않는다.
- `DEC-050`·`RULE-050`에 따라 운송사 실물 인계 뒤 `RETURN_TO_CUSTOMER` 분실·파손·배송 실패·미인수는 `DEC-038`의 실행 커밋된 결과 배분·부분 수량 범위별 연결 정정 케이스에서 처리한다. 현재 케이스 오너가 carrier simulation 예외 증거를 검토해 운송사 클레임·추적 가능한 재발송·계속 보관·대체 처분 중 경로와 추가 비용 처리를 건별 결정·기록하고, carrier simulation이 선택된 보상 사건을 실행·기록하며, 필수 증거가 갖춰진 뒤 현재 오너가 연결 정정 케이스를 종결한다. 원 resolution은 다시 열지 않고 다른 범위와 원 케이스 완료는 계속한다. 거래처 직접 인수 서명이 아직 없는 상태는 `DEC-035`의 실행 커밋 전 경계로 유지하고 운송사 실물 인계 뒤 carrier 배송 예외와 합치지 않는다. 이 결정은 해결 경로의 고정 우선순위, 추가 비용 산식, 새 필수 증거 스키마, 재시도 정책이나 새 역할을 정하지 않으므로 화면에 발명하지 않는다.
- `DEC-024`에 따라 `NO_CREDIT` 수량은 `INT-005` 로컬 창고 상태에서 판매 가능 재고를 모의 차단하고 공급사 폐기를 모의 기록하며 거래처 폐기 비용 부담을 표시한다. `DEC-047`의 통지 성립 시각부터 `DEC-049`의 연속 336시간 동안 무상 격리하고 그 순간이 지나면 보관·이의 기간을 함께 끝낸다. 주말·공휴일을 포함하고 연장하지 않으며 표시 시간대는 `DEC-055`의 IANA `Asia/Seoul`을 따른다. `DEC-035`에 따라 결과 통지·격리·금액 계산은 실행 커밋이 아니고 결정적 로컬 상태 저장소가 폐기 실행 시작을 기록한 사건부터 커밋이다. `DEC-025`에 따라 계약 우선·품목 대체 요율, 확정·조정 금액과 다음 모의 정산 차감을 표시한다. `DEC-026`에 따라 현재 케이스 오너가 소유하는 정산 예외의 재계산·재차감·미수금·회수·면제와 연결 작업 상태를 표시한다. `DEC-027`에 따라 거래처 포털은 통지 성립 시각부터 336시간이 지나기 전까지 폐기비 이의 접수·이의 금액·검토 상태·결과를, 내부 화면은 현재 오너 검토와 모의 차감 전 이의 금액 보류 또는 차감 후 사후 조정을 표시한다. 같은 참조의 보조 `SIMULATION` 이메일 실패는 재전송·현재 오너 에스컬레이션으로 표시하되 통지·물리 처리를 되돌리는 보류로 표시하지 않는다. `DEC-048`에 따라 모든 `NO_CREDIT` 수량의 폐기 증거가 기록되거나 제한 품목·격리 사고·폐기 실패·부분 성공 등 물리적 예외가 해결돼야 케이스 완료를 허용한다. 폐기비 정산 예외·이의와 연결 정산 작업은 이 물리 완료 게이트와 분리해 독립 추적하며 케이스 완료를 막지 않는다. 요율 미확정이면 확정 금액 대신 `DEC-025`·`DEC-026` 정산 예외와 근거를 표시한다. 일반 물리 실행·증거는 `DEC-051`, 제한 품목 예외는 `DEC-052`로 확정됐으며 격리 사고는 `DEC-053`으로 확정됐다. 폐기 실패·부분 성공은 `DEC-054`에서 확정한다. `UNK-023`은 `DEFERRED_NON_BLOCKING`이며 정확한 기록 보존 기간·자동 삭제 정책·삭제 증명만 후속 정책에 남는다. 모든 창고·금전·이메일 상태는 모의 원천으로 표시한다.
- `DEC-006`, `DEC-007`, `DEC-032`에 따라 케이스와 검수 화면은 생성 당시 `INT-001`의 불변 `DOGFOOD PRODUCT FIXTURE` 추적 방식 스냅샷을 읽기 전용으로 표시하며 이를 바꾸는 선택기나 수정 행동을 제공하지 않는다. 이후 fixture 변경은 기존 케이스 화면에 반영하지 않는다.
- `DEC-008`, `DEC-032`에 따라 상품 fixture 추적 방식이 없거나 지원되지 않으면 새 케이스 생성을 비활성화하고 문제가 있는 SKU와 로컬 fixture 정정 필요성을 표시한다. 실행 중 케이스를 수정하거나 실제 상품 마스터 정정 요청을 보내는 행동은 제공하지 않는다.
- `DEC-009`, `DEC-010`에 따라 시리얼 입력은 앞뒤 공백만 제거한 원문 값으로 조직 전체 중복을 차단하고, 요청·입고가 같은 물리 단위를 가리키면 하나의 시리얼 신원을 참조한다. 정정은 기존 값을 보존하는 교체 이력을 표시한다. `DEC-039`에 따라 제출 전 draft에서는 거래처 또는 현재 오너가 대리 등록한 요청의 추적값을 수정할 수 있지만, 제출 순간 고정된 원 요청 스냅샷은 덮어쓰지 않고 제출 뒤 변경은 연결 사건과 현재 오너의 감사형 반영 결정으로만 남긴다. `DEC-040`에 따라 제출 후 직접 변경 접수는 해당 시리얼·로트가 연결된 `DATA-011` 대상 품목·부분 수량 범위가 `IN_TRANSIT`가 되기 전까지만 허용한다. `IN_TRANSIT` 이후에는 `DEC-042`의 허용 경로에 해당하지 않는 일반 추적값 변경·취소를 접수하지 않으며 거래처 부담 회수 운송장 등록·추적 갱신은 이 경계와 분리한다. 현재 오너가 허용된 사건에서 추적값 변경을 반영하면 `DEC-041`의 최초 무효 단계 최소 되돌림·물리 관찰 보존·정리 증거 게이트를 적용하고, 정확한 단계·증거 매핑은 `DEC-043`으로 확정됐다. `final resolution` 최초 확정 뒤에는 `DEC-034`~`DEC-037`의 결과 배분·부분 수량별 실행 커밋 전 현재 오너 재개, 기존 기록 보존, 커밋된 범위만 재개 차단, 선택 범위 정리 게이트를 적용한다. 정리 중 시리얼 신원과 부분 수량 참조는 덮어쓰지 않고 취소·무효화·재계산·재연결 단계와 증거가 이전·새 버전에 연결되게 보존한다.
- `DEC-011`, `DEC-012`에 따라 로트 행은 번호·수량을 필수로, 제조일·유통기한·공급 로트를 선택으로 입력한다. 번호는 앞뒤 공백만 제거한 원문 값으로 비교하며 같은 케이스 품목·단계에서 여러 로트 분할과 동일 로트 행 병합을 지원하고 합계 검증을 표시한다.
- 화면의 역할별 접근 경계는 `DEC-028`로 고정됐고 공통 업무 목록·공통 케이스 요약·타임라인, 케이스 작업공간과 전문 작업공간 사이의 경로는 `DEC-058`로 확정됐다. 인증·세션·잠금·복구·감사는 `DEC-059`·`RULE-059`로 확정됐다. 모든 사용자 화면·상태의 WCAG 2.2 Level AA, 키보드·초점·스크린리더·명도 대비와 자동·핵심 흐름 수동 검사는 `DEC-060`·`RULE-060`으로 확정됐다. `SCR-003`의 휴대폰 우선·태블릿/데스크톱 전체 기능 보조와 온라인 체크포인트 복구는 `DEC-069`로 확정됐지만, 다른 화면의 기기 우선순위·추가 화면 구성·반응형 세부나 추가 브라우저·보조기술 지원 범위는 지정하지 않는다.
- `state.json.ux_coverage`는 네 화면 각각의 16개 상태 축과 22개 행동 축을 완전 매핑한다. 상태 셀 64개는 `COVERED` 61개·`N/A` 3개, 88개 screen-axis cell은 모두 존재하고, 화면별 주요 행동 4/22/12/8의 총 46개 × 22개 축인 1012개 action cell은 `COVERED` 894개·`N/A` 118개다. `OPEN`·화면 상태 간극·화면 행동 간극은 모두 0이다.
- 혼합형 화면 분리와 내비게이션은 `DEC-058`로 확정됐고, 키보드·스크린리더·명도 대비 기준은 `DEC-060`·`RULE-060`으로 확정됐다.

- 감사 문맥에는 멱등 키·입력 요약·예상 및 실제 버전·효과 참조·반환 결과를 읽을 수 있게 한다. 이 계약은 새 역할·주요 행동·케이스 전체 잠금을 추가하지 않는다.

## DEC-051~DEC-054·RULE-051~RULE-054 `NO_CREDIT` 물리 작업 화면 계약

## SCR-002 — 반품 케이스 작업공간

- `DEC-059`·`RULE-059`: 내부 사용자는 조직 SSO와 MFA를 `SIMULATION`으로 사용하고 거래처 사용자는 비밀번호와 `SIMULATION` 이메일 OTP를 사용한다. 두 경로 모두 30분 미사용 또는 8시간 절대 경과 시 세션을 만료하고 연속 5회 실패 시 30분 잠그며 각 계정 원천의 검증된 복구 흐름을 사용한다. 로그인·실패·잠금·복구를 감사 기록하고 실제 외부 SSO·이메일 연동이나 추가 인증 정책은 구현하지 않는다.
- `DEC-060`·`RULE-060`: 이 화면의 모든 사용자 상태에 WCAG 2.2 Level AA를 적용하고 키보드 전용 조작·초점 순서와 표시·스크린리더 이름·역할·상태·오류 안내·텍스트 및 비텍스트 명도 대비를 검증한다. 자동 검사와 핵심 흐름의 수동 키보드·스크린리더 검사를 모두 통과해야 하며 추가 브라우저·보조기술 지원 범위는 정하지 않는다.
- `DEC-061`·`RULE-061`: 하루 신규 케이스 200건·동시 사용자 25명·성능 시험용 보관·조회 가능 케이스 100,000건 기준 부하에서 반품 케이스 상세 요청의 95%를 2초 이내에 완료한다. 이 화면에 새 검색 기능이나 생성·변경 명령 응답 시간을 추가하지 않고 실제 보존·삭제 정책과 추가 인프라·고가용성 구조를 추정하지 않는다.
- `DEC-058`·`DEC-074`: 공통 케이스 요약·타임라인을 유지하고 승인·final resolution·예외를 이 케이스 작업공간에서 처리한다. 입고·검수·`REPLACEMENT` 출고·`NO_CREDIT` 물리 실행은 `SCR-003`의 서로 다른 전문 단계로 열며 완료 뒤 이 공통 케이스 문맥으로 돌아온다.
- `DEC-053`: 현재 오너에게 영향 범위 보류, 로컬 창고 상태·인계·보관 증거 검토, 책임·비용과 산정 근거·복구·종결 조건 결정, 창고 복구 배정, 필수 증거 검토·해결 확정을 제공한다. 근거 또는 실행 증거가 없으면 해당 범위만 보류한다.
- `DEC-054`: 현재 오너에게 폐기 실패·부분 성공 범위의 성공 처분 사실·수량과 실패·잔여 수량 분리, 로컬 창고 상태·폐기 인계·실행 증거 검토, 책임·추가 비용과 산정 근거·재시도 또는 대체 처분·잔여 수량·종결 조건 결정, 창고 복구 배정, 필수 증거 검토·해결 확정을 제공한다. 성공 사실·수량은 읽기 전용으로 보존하고 근거 또는 실행 증거가 없으면 실패·잔여 범위만 보류한다.

- `DEC-044`: 생성·제출·승인·final resolution·실행 동작에 최초 멱등 키와 대상 범위 예상 버전을 결속한다. 같은 입력 재시도에는 기존 결과, 다른 입력 또는 버전 불일치에는 충돌·최신 상태를 표시하며 simulation에는 범위·resolution 버전·동작별 유일 실행 참조를 보여 준다.
- `DEC-045`: 현재 오너와 배정된 창고·정산 담당자의 역할별 작업함 알림을 표시하고, 지연·실행 실패·정산 예외에만 `SIMULATION` 이메일 에스컬레이션 기록을 표시한다. 실제 이메일 전달이나 전달 실패에 따른 업무 전이는 표현하지 않는다.
- `DEC-046`: 현재 케이스 오너에게만 해당 케이스의 전체 내부 패키지 다운로드를 제공한다. 비오너 RMA Agent·창고·정산 담당자에게 전체 내부 패키지나 배정 문맥 밖 일괄 다운로드를 제공하지 않고, 어떤 역할에도 자동 삭제 설정·실행이나 수동 hard-delete UI를 제공하지 않는다. 지원 증빙은 JPG·PNG·PDF만 표시·업로드하고 영상을 제공하지 않는다.
- `DEC-047`: 현재 오너 작업공간에는 필수 통지 내용 스냅샷, 단일 통지 참조, 포털 원자 게시 커밋·거래처 조회 가능 시각·연속 336시간 시작, 같은 참조의 이메일 시도·실패·재전송과 현재 오너 에스컬레이션을 표시한다. 별도 수령 확인이나 이메일 성공을 기산 조건으로 제공하지 않고 이메일 실패가 통지·물리 처리를 되돌리는 행동을 만들지 않는다.
- `DEC-048`: 모든 `NO_CREDIT` 결과 배분·부분 수량의 폐기 증거 또는 물리적 예외 해결 상태를 모아 보여 주고, 미해결 물리적 예외가 없을 때만 현재 오너의 케이스 완료 행동을 활성화한다. 정산 예외·이의·연결 정산 작업은 독립 추적하며 이 완료 행동의 차단 조건으로 사용하지 않는다.
- `DEC-076`: 케이스 완료 직전에 범위별 완료 증거, 원 케이스 완료를 막는 미해결 항목이 없다는 판정, 완료 뒤 독립 유지 작업과 종결 효과를 표시한다. 현재 오너가 명시 확인한 때만 완료하며 취소하면 `ACTIVE`와 저장 입력을 유지하고 완료 사건을 만들지 않는다. 완료 뒤 undo·원 케이스 재개는 제공하지 않고 새 오류·분쟁은 `DEC-038` 연결 정정으로 표시하며 확인 또는 취소 결과를 감사한다.
- `DEC-049`: 현재 오너 작업공간은 단일 통지 참조의 성립 시각, 연속 336시간 종료·이의 마감·폐기 예정 기준과 계산 근거를 표시한다. 이메일 상태나 수령 확인으로 이 시각을 바꾸는 행동은 제공하지 않는다.
- `DEC-050`: 현재 오너에게 연결 정정 대상 범위와 carrier simulation 예외 증거를 제시하고 운송사 클레임·추적 가능한 재발송·계속 보관·대체 처분 중 경로와 추가 비용 처리의 건별 결정·기록, simulation 결과·필수 증거 확인, 연결 정정 케이스 종결 동작을 제공한다. 원 resolution 재개 동작과 고정 경로 우선순위는 제공하지 않는다.
- `DEC-062`: 현재 오너에게 `RETURN_TO_CUSTOMER` 운송사 배송의 실물 인계·carrier simulation 운송 접수 성공·결과 배분/부분 수량 범위별 확정 `KRW` 운임·착불 상태를 표시한다. 라벨 값은 미확정으로 구분하고 착불 회수 성공과 배송 완료의 단일 성공 사건, 회수 실패의 배송 완료 비표시와 `DEC-050` 연결 정정 참조를 함께 표시한다. 실제 외부 결제·청구 동작이나 직접 인수 비용 필드는 제공하지 않는다.
- `DEC-063`: 결정적 로컬 주문 fixture의 원 납품처 주소·수령 연락처 원값과 거래처의 자기 조직 기본값 확인 또는 대체 값 요청을 표시한다. 현재 케이스 오너에게만 실물 인계 전 목적지·연락처 스냅샷 확정 행동을 제공하고, 원값·요청값·확정값·사유·수행자·시각을 감사 문맥으로 연결한다. 원 fixture 덮어쓰기·주소록·실제 외부 주소 검증·라벨 연동은 제공하지 않는다.
- `DEC-051`: 현재 오너에게 `NO_CREDIT` 결과 배분·부분 수량별 판매 가능 재고 차단·격리 위치 이동과 관리·폐기 인계와 실행 작업 배정, 배정 창고 담당자·원천·필수 증거 상태, 예외와 완료 검토·확정 동작을 제공한다. 현재 오너가 물리 전문 필드를 대신 기록하는 동작은 제공하지 않는다.
- `DEC-057`: 대리 접수 draft·추가정보 보완·연결 정정·`NO_CREDIT` 검토에서 JPG·PNG·PDF, 파일당 20 MB, 파일 개수·제출 단위 총량 무상한을 표시한다. 확장자·MIME·시그니처 일치와 결정적 로컬 악성 파일 검사를 모두 통과한 파일만 확정한다. 실패·시간 초과·검사기 오류 파일은 비확정·사유·재선택을 표시하고 다른 유효한 Draft 입력·기존 안전 첨부를 보존하며 실패·재업로드를 같은 업무 참조의 감사 이력으로 연결한다. 비동기 격리 상태는 제공하지 않는다.
- `DEC-072`: 대리 등록 draft 작성·증빙 업로드·제출에서 성공한 서버 저장만 권위 체크포인트로 표시하고, 연결 단절·불안정 중 새 저장·제출을 차단한다. 현재 열린 탭의 미전송 입력만 임시 유지해 저장분·미저장분을 구분하며, 재연결 시 같은 멱등 키·예상 범위 버전으로 다시 저장한다. 충돌하면 최신 서버 상태를 먼저 읽고 자동 병합하지 않는다. 탭 종료·새로고침·세션 만료 뒤에는 마지막 서버 체크포인트에서 재개하며 기기 영구 저장·오프라인 편집·제출·동기화는 제공하지 않는다.
- `DEC-066`: 현재 오너에게 `REPLACEMENT` 후보 결과 배분·부분 수량 범위의 결정적 로컬 재고 전량 예약, 성공 범위 최초 확정·출고 준비, SERIAL 또는 LOT 새 출고 추적값 기록과 창고 출고 작업 배정을 제공한다. 예약 실패 범위에는 확정을 차단하고 수량 축소 또는 `REFUND` 재결정만 제공한다. 같은 유일 실행 참조에 배정 창고 담당자의 로컬 재고 출고 차감과 carrier simulation 운송 접수 성공이 모두 기록되기 전에는 미커밋으로, 모두 기록된 뒤에는 커밋·잠금으로 표시한다.

- 기록 수명주기 표시/행동: 정확한 보존 기간·자동 삭제 정책·삭제 증명은 표시하거나 추정하지 않는다. 자동 삭제 설정·실행과 수동 hard-delete를 제공하지 않으며, 대리 등록의 제출 전 `draft 삭제`는 제출 이후 기록 hard-delete와 구분한다.
- 요청 변경 표시/행동: 현재 케이스 오너는 전화·이메일 대리 등록 draft의 품목·부분 수량·사유·증빙·추적값을 제출 전 수정하거나 draft를 삭제할 수 있다. draft 삭제 시 `DEC-073`에 따라 서버 저장분과 현재 탭 미저장분을 분리 표시한 명시 확인을 요구하고, 확인하면 즉시 둘 다 삭제해 복구·undo를 제공하지 않으며 취소하면 모두 유지하고 결과를 감사한다. 제출 순간 고정된 원 요청 스냅샷은 읽기 전용으로 유지하고, 제출 뒤에는 원 스냅샷에 연결된 변경·취소 요청 또는 정정 사건과 대상 범위·감사 이력을 검토해 반영 여부를 결정한다. `DEC-040`에 따라 대상 `DATA-011` inbound 범위별 반품 운송 상태·`IN_TRANSIT` 전이 시각과 그때부터 거래처 직접 접수가 닫힌 판정을 표시한다. 운송장 등록만으로는 닫지 않고 다른 범위·outbound `RETURN_TO_CUSTOMER` 배송과 구분한다. `DEC-042`에 따라 보완은 현재 오너가 승인 또는 입고 불일치 재결정을 위해 연 추가정보요청의 증빙·답변으로 제한하고, 이의는 `DEC-047` 통지 성립 시각부터 336시간이 지나기 전의 `NO_CREDIT` 폐기비만 허용한다. 최초 `final resolution` 확정 뒤 미커밋 범위는 현재 오너가 정정 필요를 결정한 때만 `DEC-041`·`DEC-037`을 적용해 재개하고, 실행 커밋 뒤 오류·분쟁은 `DEC-038` 연결 정정으로 처리한다. 그 밖의 일반 변경·취소는 접수하거나 새 보완으로 우회하지 않으며 혼합 쟁점은 쟁점·대상 범위별로 나눈다. 현재 오너가 허용된 사건의 반영을 결정하면 `DEC-041`에 따라 변경 필드가 처음 무효화하는 단계까지만 대상 범위를 되돌리는 상태, 보존된 운송·입고·검수 관찰, 무효 미커밋 지시·결정·참조의 취소·재연결 증거와 전체 확인 전 재처리 차단을 표시한다. 필드·목적별 고정 최소 단계·증거 동작은 `DEC-043`의 확정 매핑을 사용하며 임의 매핑을 제공하지 않는다.
- 확정 표시/행동: `DEC-039`에 따라 현재 케이스 오너에게 준비된 품목·부분 수량별 `final resolution` 후보 코드·수량·사유와 독립 최초 확정 행동을 제공하고 같은 Return Line의 결과 배분·부분 수량 범위별 최초 확정 기록·현재 활성 버전·`COMMITTED` 또는 `UNCOMMITTED` 상태와 혼재 요약을 표시한다. `REFUND`는 `DEC-067`의 `TRANSFER_ACCEPTED`부터 해당 범위만 지급 커밋으로 잠그고, 이체 요청·`TRANSFER_ACCEPTED` 전 실패는 미커밋으로 표시하며, 같은 참조의 `TRANSFER_SETTLED`와 필수 증거를 실행 완료로 표시한다. `RETURN_TO_CUSTOMER`는 참조 범위의 운송사 실물 인계 또는 거래처 직접 인수 서명, `NO_CREDIT`는 참조 범위의 폐기 실행 시작부터 해당 범위만 커밋으로 잠그며 라벨 생성·결과 통지·격리·금액 계산 단계에서는 미커밋으로 표시한다. `DEC-042`에 따라 현재 오너가 정정 필요를 결정한 적격 미커밋 범위에만 필수 사유와 감사 이력을 남기는 재개를 제공하고, 재개 없이 기존 확정 결과대로 계속 처리할 수도 있다. 재개를 시작하면 `DEC-041`·`DEC-037`에 따라 선택 범위만 잠그고 새 실행을 차단한 뒤 미커밋 운송·정산 실행 지시 취소·무효화 → 재고·격리·금액 참조 재계산·재연결 → 기존 통지 `SUPERSEDED`·정정 통지 `PENDING` → 단계별 증거 확인을 순서대로 표시한다. 모든 필수 증거가 성공하기 전에는 새 resolution 버전 활성화를 차단하고, 성공하면 현재 오너에게 새 버전 활성화를 허용하며, 실패하면 해당 범위만 `REOPEN_CLEANUP_HOLD`로 유지한다. 커밋된 범위에는 재개 행동을 제공하지 않고 재개 불가 상태와 커밋 근거를 표시하며 다른 미커밋 형제 범위와 품목은 계속 처리한다. 기존 확정 기록은 읽기 전용으로 보존하고 수행자·시각·필수 사유·범위 참조·부분 수량·이전·새 값·단계별 증거·이전·새 버전의 감사 이벤트를 추가한다. 후속 실행·예외·이의·금액 조정은 범위·버전과 연결해 구분한다.
- `DEC-066` 확정·커밋 표시/행동: `REPLACEMENT` 후보 범위의 전량 예약 성공 전에는 최초 확정 행동을 비활성화하고 실패 이유와 수량 축소 또는 `REFUND` 재결정을 표시한다. 성공 범위는 확정·출고 준비·새 추적값·배정 창고 작업을 연결해 표시하되 로컬 출고 차감과 carrier 운송 접수 성공이 같은 유일 실행 참조에 모두 기록되기 전까지 `UNCOMMITTED`, 이후 `COMMITTED`·재개 불가로 표시한다.
- 연결 정정 표시/행동: `DEC-042`·`DEC-038`에 따라 실행 커밋 뒤 오류·분쟁 범위에는 원 케이스·범위·resolution 버전·커밋 증거를 불변 참조하는 별도 연결 정정 케이스를 표시한다. 현재 케이스 오너에게만 정정·보상 유형·사유·증빙 결정 동작을 제공하고 해당 carrier·warehouse·settlement simulation 보상 사건과 결과를 연결한다. `DEC-077`에 따라 보상 사건 직전 원 참조·결정·증빙·simulation별 불가역 효과·현재 정정 케이스 버전을 상세 표시하고 현재 오너가 확인한 버전의 유일 실행 참조로만 사건을 시작한다. 취소하면 저장 입력·체크포인트를 유지하고, 실행 커밋된 결정·사건은 수정·취소·재개하지 않으며 추가 오류·분쟁은 같은 연결 정정 케이스에 원 사건을 불변 참조하는 새 후속 사건으로 추가한다. `DEC-050`의 `RETURN_TO_CUSTOMER` carrier 배송 예외에는 현재 오너의 건별 경로·추가 비용 처리 결정·기록, carrier simulation 결과와 필수 증거 확인, 연결 정정 케이스 종결을 제공하되 원 resolution 재개는 제공하지 않는다. 다른 범위와 원 케이스 완료는 계속 처리한다.
- 읽기/쓰기 데이터: `DATA-001`~`DATA-005`, `DATA-010`~`DATA-013`. 대리 등록 draft의 품목·부분 수량·사유·증빙·추적값은 제출 전 수정·삭제할 수 있고, 제출 순간 고정된 원 요청 스냅샷은 읽기 전용으로 유지하며 연결 변경·취소 사건·현재 오너 반영 판단·감사 이력만 별도 추가한다. `DATA-011` inbound 범위별 반품 운송 상태·`IN_TRANSIT` 전이 사건·시각과 직접 접수 마감 판정을 읽고 원 스냅샷·연결 사건 계보와 구분한다. 현재 케이스 오너만 선택 범위 잠금·새 실행 차단·정리 게이트와 필수 정리 성공 뒤 새 버전 활성화를 통제한다. 배정된 창고 담당자는 연결된 미커밋 창고·재고·격리 참조의 취소·무효화·재연결 상태와 증거, 배정된 `REFUND` 정산 담당자는 미커밋 정산 지시 취소·무효화·금액 참조 재계산·재연결 상태와 증거만 자기 배정 문맥에 기록한다. 다른 범위와 역할의 데이터는 읽기 전용이거나 보이지 않으며, 단계마다 `DATA-004` 감사 이력에 범위·부분 수량·수행자·시각·이전·새 값·원천·증거를 남긴다.
- `DEC-066` 읽기/쓰기 데이터: 현재 오너는 `DATA-005`의 `REPLACEMENT` 후보 범위 전량 예약 요청·결과, 최초 확정, 새 출고 추적값과 창고 출고 작업 배정을 기록한다. 배정 창고 담당자의 로컬 재고 출고 차감과 carrier simulation 운송 접수 결과는 같은 범위·resolution 버전·동작의 유일 실행 참조로 읽고, 둘이 모두 성공한 때의 커밋 판정과 감사 계보를 표시한다.
- `DEC-067` 읽기/쓰기 데이터: 현재 오너의 `REFUND` 범위 정산 배정과 배정 정산 담당자의 금액·결정적 로컬 계좌 스냅샷 확인·이체 요청을 `DATA-005`에 연결한다. 같은 유일 실행 참조의 `TRANSFER_ACCEPTED` 접수 시각과 `TRANSFER_SETTLED`의 금액·`KRW`·계좌 스냅샷 참조·완료 시각·결과 참조, 커밋 전 실패·커밋 뒤 `DEC-038` 참조를 읽고 역할별 쓰기 경계를 유지한다.
- Dogfood 데이터 경계: 불변 fixture 주문·Order Line·상품·정책·상업 스냅샷과 carrier·settlement simulation 및 로컬 창고 상태를 출처별로 표시하고, 실제 API·웹훅·배치·외부 운영 원장 파일 연동과 실제 외부 부수효과를 제공하지 않는다. 현재 오너의 역할 제한 내부 케이스 패키지와 조직 전체 조회 권한 RMA Agent의 제한 분석 CSV는 RMA 앱 로컬 산출물이며 이 외부 파일 연동 금지에 해당하지 않는다.

## SCR-003 — 창고 전문 작업공간

- `DEC-059`·`RULE-059`: 내부 사용자는 조직 SSO와 MFA를 `SIMULATION`으로 사용하고 거래처 사용자는 비밀번호와 `SIMULATION` 이메일 OTP를 사용한다. 두 경로 모두 30분 미사용 또는 8시간 절대 경과 시 세션을 만료하고 연속 5회 실패 시 30분 잠그며 각 계정 원천의 검증된 복구 흐름을 사용한다. 로그인·실패·잠금·복구를 감사 기록하고 실제 외부 SSO·이메일 연동이나 추가 인증 정책은 구현하지 않는다.
- `DEC-060`·`RULE-060`: 이 화면의 모든 사용자 상태에 WCAG 2.2 Level AA를 적용하고 키보드 전용 조작·초점 순서와 표시·스크린리더 이름·역할·상태·오류 안내·텍스트 및 비텍스트 명도 대비를 검증한다. 자동 검사와 핵심 흐름의 수동 키보드·스크린리더 검사를 모두 통과해야 하며 추가 브라우저·보조기술 지원 범위는 정하지 않는다.
- `DEC-061`·`RULE-061`: 하루 신규 케이스 200건·동시 사용자 25명·성능 시험용 보관·조회 가능 케이스 100,000건 기준 부하에서 입고 검수 전문 작업 상세 요청의 95%를 2초 이내에 완료한다. 이 화면에 새 검색 기능이나 생성·변경 명령 응답 시간을 추가하지 않고 실제 보존·삭제 정책과 추가 인프라·고가용성 구조를 추정하지 않는다.
- `DEC-058`·`DEC-074`: 입고·검수·`REPLACEMENT` 출고·`NO_CREDIT` 물리 실행을 서로 다른 전문 단계로 제공한다. 역할별 작업함은 배정된 전문 작업으로 직접 진입하고 완료 뒤 공통 케이스 요약·타임라인으로 돌아온다. 승인·final resolution·예외 결정은 `SCR-002`에 남긴다.
- `DEC-069`: 창고 검수 전체 편집은 휴대폰을 1순위로 하고 태블릿·데스크톱을 같은 전체 기능 보조로 지원한다. 오프라인 편집·제출·동기화와 기기 로컬 초안은 제공하지 않는다. 연결이 불안정하면 성공한 서버 체크포인트와 미저장 상태를 구분해 표시하고 제출을 차단한 뒤 같은 멱등 키·범위 버전으로 재시도한다. 전면 장애에는 `DEC-056` 수기 대기열을 사용하며 기기 로컬 저장·오프라인 동기화·자동 병합을 제공하지 않는다.
- `DEC-044`: 입고·검수 제출과 불일치 상태 전이에 같은 멱등 키와 품목·부분 수량 범위 예상 버전을 사용하고 중복 제출에는 새 기록 대신 기존 진행·결과를 표시한다.

- `DEC-048`: 배정 문맥의 `NO_CREDIT` 폐기 증거 기록 여부와 물리적 예외 상태, 전체 케이스의 물리 완료 게이트를 필요한 범위에서 읽기 전용으로 표시한다. 창고 담당자는 배정된 전문 필드만 기록하며 케이스 완료나 정산 예외 상태를 결정하지 않는다.
- `DEC-049`: 창고 담당자는 배정 문맥의 통지 성립 시각과 336시간 뒤 보관·이의 종료·폐기 예정 기준을 읽기 전용으로만 본다. 기간 변경·연장 행동은 제공하지 않는다.
- `DEC-050`: 현재 오너와 carrier simulation의 연결 정정 경로이므로 창고 전문 작업공간에 새 결정·보상 실행 동작을 추가하지 않는다. 배정 문맥에 필요한 외부 공개 상태만 읽기 전용으로 표시한다.

- `DEC-057`: 검수·`NO_CREDIT` 물리 작업의 증빙은 JPG·PNG·PDF, 파일당 20 MB, 파일 개수·제출 단위 총량 무상한을 표시한다. 확장자·MIME·시그니처 일치와 결정적 로컬 악성 파일 검사를 모두 통과한 파일만 확정한다. 실패·시간 초과·검사기 오류 파일은 비확정·사유·재선택을 표시하고 다른 유효한 Draft 입력·기존 안전 첨부를 보존하며 실패·재업로드를 같은 업무 참조의 감사 이력으로 연결한다. 비동기 격리 상태는 제공하지 않는다.
- `DEC-065`: 품목·부분 수량별 포장 상태는 `INTACT`·`DAMAGED_OR_OPENED`, 제품 상태는 `NORMAL`·`DEFECT_CONFIRMED`, 재판매 가능성은 `YES`·`NO`만 선택한다. 단순 반품의 포장·외관·구성품, 불량의 신고 증상·기능 재현·외관·구성품, 오배송의 요청·승인 대비 실제 SKU·수량·추적값과 상품 라벨, 추적 불일치의 요청·승인 추적값과 실제 입고 추적값 체크를 해당 사유에 표시한다. 손상·불량·오배송·추적 불일치에는 공통 증빙 기준을 적용한다.
- `DEC-054`: 현재 오너가 배정한 폐기 실패·부분 성공의 실패·잔여 범위에 한해 선택된 재시도·대체 처분 실행과 DEC-051 필수 증거 기록 동작을 제공한다. 관찰 사실과 성공 처분 수량은 읽기 전용으로 보존하며, 책임·추가 비용·복구 경로·종결 조건 결정과 보류 해제 동작은 제공하지 않는다.

- 진입: 역할별 작업함에서 현재 케이스 오너가 배정한 입고·검수 작업, `DEC-074` `REPLACEMENT` 출고 작업 또는 `DEC-051` `NO_CREDIT` 물리 작업의 분리된 단계로 직접 진입한다. `USR-004`는 배정된 작업과 필요한 문맥만 볼 수 있으며 완료 뒤 공통 케이스 요약·타임라인으로 돌아온다.
- 행위자: 배정된 `USR-004` 창고 담당자는 입고·검수 전문 필드, `DEC-074` `REPLACEMENT` 출고의 범위 상세 확인·로컬 재고 차감·carrier simulation 인계와 같은 유일 실행 참조, `DEC-037` 정리 때 자기 배정 문맥에 연결된 미커밋 창고·재고·격리 참조의 취소·무효화·재연결 상태·증거, `DEC-051` `NO_CREDIT` 물리 작업의 재고 차단·격리 위치·폐기 인계와 실행·필수 증거만 기록한다. 현재 케이스 오너는 작업을 범위별로 배정하고 예외·완료·필수 증거를 검토·확정하며, final resolution·면제·케이스 완료와 새 resolution 버전 활성화는 `SCR-002`에서만 통제한다.

- 요청 스냅샷 표시: 배정된 검수에 필요한 범위에서 제출 순간 고정된 원 요청의 SKU·수량·추적값·증빙을 읽기 전용으로 표시하고, 현재 케이스 오너가 반영하기로 결정한 연결 변경·취소 요청 또는 정정 사건의 적용 계보를 원 스냅샷과 구분해 표시한다. 배정 범위의 `DATA-011` inbound 반품 운송 상태와 `IN_TRANSIT` 전이 시각, 그 시점부터 거래처 직접 변경·취소 접수가 닫힌 상태를 읽기 전용으로 표시한다. `DEC-042`에 따라 승인 또는 입고 불일치 재결정을 위해 현재 오너가 연 추가정보요청의 보완 상태만 검수 문맥에서 표시하고, 폐기비 이의·현재 오너 재개·커밋 뒤 연결 정정은 관련 상태만 읽기 전용으로 표시한다. 일반 변경·취소 접수나 다른 경로 전환 행동은 제공하지 않고 혼합 쟁점은 배정된 쟁점·대상 범위별로 분리해 표시한다. `DEC-041`에 따라 이전 운송·입고·검수 관찰은 삭제·되감지 않고 보존 상태로 표시하며, 무효가 된 미커밋 창고 지시·결정·참조의 취소·재연결 증거 게이트를 원 관찰과 구분해 읽기 전용으로 보여준다. 창고 담당자는 원 제출값·물리 관찰·현재 오너의 반영 결정·마감·경로 판정을 변경하지 않는다. 필드·목적별 고정 최소 시작 단계와 증거는 `DEC-043`의 확정 매핑으로 표시한다.
- 확정 표시/행동: `DEC-039`에 따라 배정된 검수 문맥에 준비된 품목·부분 수량별 독립 `final resolution` 최초 확정·현재 활성 버전·`COMMITTED` 또는 `UNCOMMITTED`·재개 상태와 혼재 요약을 필요한 범위에서 읽기 전용으로 표시한다. `RETURN_TO_CUSTOMER` 운송사 실물 인계·거래처 직접 인수 서명과 `NO_CREDIT` 폐기 실행 시작은 참조 범위만 커밋하고 라벨 생성·결과 통지·격리·금액 계산은 비커밋 준비 상태로 구분한다. `DEC-037` 정리 중에는 선택 범위의 새 실행 차단, 연결된 미커밋 창고 작업 취소·무효화, 재고·격리 참조 재계산·재연결과 단계별 증거, 성공 뒤 새 활성 버전 또는 실패한 범위의 `REOPEN_CLEANUP_HOLD`를 표시한다. 창고 담당자는 자기 배정 문맥의 정리 상태·증거만 기록하고 `final resolution` 결정·최초 확정·재개·새 버전 활성화는 할 수 없다. 커밋된 범위와 다른 미커밋 형제 범위·품목·배정 작업은 계속 처리한다.
- 읽기/쓰기 데이터: 제출 순간 고정된 `DATA-002` 원 요청 스냅샷과 `DATA-006`·`DATA-007`의 요청 추적 관찰, 현재 오너가 반영한 연결 사건 계보는 필요한 범위에서 읽기 전용으로 확인한다. 배정된 `DATA-003`의 실제 SKU·수량·추적값, 포장 `INTACT`/`DAMAGED_OR_OPENED`, 제품 `NORMAL`/`DEFECT_CONFIRMED`, 재판매 `YES`/`NO`, 사유별 고정 체크와 공통 증빙, `DEC-037` 정리 때 배정 문맥의 미커밋 창고·재고·격리 참조 상태·증거를 변경한다. `DEC-074`의 배정된 `REPLACEMENT` 출고에서는 `DATA-005`의 결과 배분·부분 수량·resolution 버전·시리얼 또는 로트·새 추적값·재고 전후·불가역 효과·범위 버전·명시 확인 결과·로컬 재고 차감 결과·carrier simulation 인계와 운송 접수 결과·같은 유일 실행 참조 및 `DATA-013` 전문 작업 상태를 기록한다. `DEC-051`의 배정된 `NO_CREDIT`에서는 `DATA-013`의 판매 가능 재고 차단·격리 위치 이동과 관리·폐기 인계와 실행·필수 증거를 변경하고 각 전문 작업은 `DATA-004` 감사 이력을 남긴다. `DATA-011` 회수 운송장과 케이스·품목·final resolution 코드·수량·버전·정리 게이트·현재 오너의 예외·완료 판정은 읽기 전용이다. `DEC-030`의 outbound `RETURN_TO_CUSTOMER` 실행, final resolution·면제·예외 해결·케이스 완료는 이 화면에서 변경하지 않는다.
- Dogfood 데이터 경계: 입고·검수 관찰, `REPLACEMENT` 로컬 재고 출고 차감, `NO_CREDIT` 재고 차단·격리·처분은 결정적 로컬 창고 상태 저장소에 기록한다. carrier simulation의 inbound 회수 상태와 `REPLACEMENT` outbound 인계·운송 접수 결과를 해당 결과 배분·부분 수량·resolution 버전·유일 실행 참조에 연결하고 실제 창고·재고·운송 시스템에는 쓰지 않는다. 모든 로컬·모의 상태를 명시한다.
- 확정: 중복 갱신·재시도 복구(`DEC-044`), 증빙·삭제·다운로드 경계(`DEC-046`), 파일 검증(`DEC-057`), 엄격한 2값 검수(`DEC-065`), `NO_CREDIT` 물리 계약(`DEC-047`~`DEC-054`), 지역화(`DEC-055`), 휴대폰 우선 온라인 체크포인트(`DEC-069`), 불가역 커밋 상세 확인(`DEC-071`)을 적용한다. `DEC-074`에 따라 배정 창고 담당자의 `REPLACEMENT` 출고는 이 전문 작업공간의 별도 단계에서 실행하고 입고·검수·`NO_CREDIT` 단계와 분리한다. 연결 정정 결정은 `SCR-002`에 남기고 `DEC-077`에 따른 실행 상태는 필요한 배정 문맥에서 읽기 전용으로만 표시한다. 후속 정책은 `UNK-023`이고 현재 `OPEN` material unknown은 없으며 `project.next_question`은 `null`이다. `DEC-070` 운영 분석은 `SCR-001`에만 제공한다.

## SCR-004 — 거래처 반품 포털

- `DEC-059`·`RULE-059`: 내부 사용자는 조직 SSO와 MFA를 `SIMULATION`으로 사용하고 거래처 사용자는 비밀번호와 `SIMULATION` 이메일 OTP를 사용한다. 두 경로 모두 30분 미사용 또는 8시간 절대 경과 시 세션을 만료하고 연속 5회 실패 시 30분 잠그며 각 계정 원천의 검증된 복구 흐름을 사용한다. 로그인·실패·잠금·복구를 감사 기록하고 실제 외부 SSO·이메일 연동이나 추가 인증 정책은 구현하지 않는다.
- `DEC-060`·`RULE-060`: 이 화면의 모든 사용자 상태에 WCAG 2.2 Level AA를 적용하고 키보드 전용 조작·초점 순서와 표시·스크린리더 이름·역할·상태·오류 안내·텍스트 및 비텍스트 명도 대비를 검증한다. 자동 검사와 핵심 흐름의 수동 키보드·스크린리더 검사를 모두 통과해야 하며 추가 브라우저·보조기술 지원 범위는 정하지 않는다.
- `DEC-058`: 자기 조직의 외부 공개 케이스 요약·타임라인만 기존 권한 범위에서 표시한다. 내부 역할별 작업함이나 입고·검수·`NO_CREDIT` 물리 전문 작업공간 진입은 제공하지 않으며 기존 외부 공개 권한을 넓히지 않는다.
- `DEC-044`: draft 생성·제출·연결 변경·회수 추적 갱신·이의 제출에 최초 멱등 키를 재사용한다. 같은 입력 재시도에는 기존 결과, 다른 입력·버전 불일치에는 충돌과 최신 외부 공개 상태를 자기 조직 범위에서 표시한다.
- `DEC-045`: 자기 조직 포털 알림함을 지속 조회하는 기준 원장(실제 보존 기간 아님)으로 표시하고 지정 사건의 `SIMULATION` 이메일 기록을 함께 표시한다.
- `DEC-046`: 거래처 사용자에게 자기 거래처 조직의 외부 공개 케이스 패키지 다운로드만 제공하고 내부 전체 패키지·다른 조직 패키지·일괄 다운로드·자동 삭제 설정·실행·수동 hard-delete 동작은 제공하지 않는다. 증빙 선택·업로드는 JPG·PNG·PDF만 허용하고 영상을 제공하지 않는다.
- `DEC-057`: 요청 draft·열린 추가정보요청 보완의 증빙에 JPG·PNG·PDF, 파일당 20 MB, 파일 개수·제출 단위 총량 무상한을 표시한다. 확장자·MIME·시그니처 일치와 결정적 로컬 악성 파일 검사를 모두 통과한 파일만 확정한다. 실패·시간 초과·검사기 오류 파일은 비확정·사유·안전한 파일 재선택을 표시하고 다른 유효한 Draft 입력·기존 안전 첨부를 보존하며 실패·재업로드를 같은 업무 참조의 감사 이력으로 연결한다. 비동기 격리 상태는 제공하지 않는다.
- `DEC-072`: 요청 draft 작성·증빙 업로드·제출에서 성공한 서버 저장만 권위 체크포인트로 표시하고 연결 단절·불안정 중 새 저장·제출을 차단한다. 현재 열린 탭의 미전송 입력만 임시 유지해 저장분·미저장분을 구분한다. 재연결 시 같은 멱등 키·예상 범위 버전으로 다시 저장하고 충돌하면 자기 조직의 최신 서버 상태를 먼저 읽으며 자동 병합하지 않는다. 탭 종료·새로고침·세션 만료 뒤에는 마지막 서버 체크포인트에서 재개하고 기기 영구 저장·오프라인 편집·제출·동기화는 제공하지 않는다.
- `DEC-047`: 자기 조직 `NO_CREDIT` 통지에는 필수 공개 내용·단일 통지 참조·포털 원자 게시 성립 시각·14일 이의 마감을 표시하고 같은 참조의 보조 이메일 상태·재전송을 분리해 표시한다. 거래처 수령 확인 행동을 기산 조건으로 제공하지 않으며 이메일 실패가 통지·물리 처리를 되돌리지 않음을 표시한다.
- `DEC-048`: 자기 조직의 `NO_CREDIT` 결과 배분·부분 수량별 폐기 완료 또는 물리적 예외 상태와 케이스 완료 여부를 외부 공개 범위에서 표시한다. 폐기비 정산 예외·이의 상태는 물리 완료 상태와 구분하고 거래처 사용자에게 완료 결정 행동을 제공하지 않는다.
- `DEC-049`: 거래처 사용자는 자기 조직 통지의 성립 시각과 정확히 336시간 뒤의 보관·이의 종료·폐기 예정 기준을 확인하고 그 마감 전까지만 폐기비 이의를 접수한다. 주말·공휴일 포함·연장 없음과 `DEC-055`의 IANA 표시 시간대 `Asia/Seoul`을 함께 표시하되 시간대가 기간 길이를 바꾸는 것으로 표현하지 않는다.
- `DEC-050`: 자기 조직의 연결 정정 케이스 중 기존 권한 계약에서 외부 공개 대상으로 분류된 상태와 결과만 읽기 전용으로 표시한다. 원 resolution 비재개와 다른 범위·원 케이스 완료 계속을 표시하고 거래처 결정 동작이나 구체 공개 필드를 추가하지 않는다.
- `DEC-062`: 자기 조직 `RETURN_TO_CUSTOMER` 운송사 배송 범위의 carrier simulation 운송 접수 성공 뒤 확정 `KRW` 운임과 거래처 수취 착불 상태를 공개한다. 라벨 값은 확정 금액으로 표시하지 않는다. 착불 회수 성공과 배송 완료를 하나의 성공 사건으로 표시하고 회수 실패는 배송 완료가 아니라 `DEC-050` 배송 실패·미인수 연결 정정 상태로 표시한다. 외부 결제·청구 행동이나 직접 인수 비용은 제공하지 않는다.
- `DEC-063`: 자기 조직의 결정적 로컬 주문 fixture 원 납품처 주소·수령 연락처를 기본값으로 표시하고 거래처 사용자가 확인하거나 대체 값을 요청할 수 있게 한다. 현재 오너가 운송사 인계 전에 확정한 목적지·연락처 스냅샷과 상태는 읽기 전용으로 표시한다. 다른 조직 값·현재 오너 확정 동작·원 fixture 덮어쓰기·주소록·실제 외부 주소 검증·라벨 연동은 제공하지 않는다.

- 진입: `DEC-059`·`RULE-059`의 거래처 비밀번호·`SIMULATION` 이메일 OTP 인증 후 자기 거래처 조직의 포털. `DEC-028`에 따라 외부 공개 정보만 조회하고 허용된 요청·보완·이의만 제출한다.
